# 第4层设计备忘（用户自由搭建攀爬架）

这里记录在第3层确定、必须带入第4层的要求。第4层设计开始时并入正式设计文档。

## 1. 玩家搭建的结构必须报告未通过几何检查的比例（2026-11-11用户决定）

- **要求**：在玩家搭建的结构上统计成功率时，必须同时报告：
  - 未通过几何可行性检查（`BoxStackFeasibility.Check`）的结构数及比例；
  - 脚本控制器在这些结构上的完成数。
- **原因**（【数据】，[LAYER3_FEASIBILITY_AUDIT.md](LAYER3_FEASIBILITY_AUDIT.md) §3）：
  - 几何检查比脚本控制器的实际能力保守。在v1 Hard的30个结构中，几何检查全部判为不可行，而脚本控制器完成了其中16个（踏面0.15–0.30m，靠双手和部分支撑过渡，不在任务意义上"站稳"）。
  - 第3层的完成标准只在通过几何检查的结构上计算成功率（[LAYER3_DESIGN.md](LAYER3_DESIGN.md) §16）。v2评估集全部通过，所以没有影响。但玩家搭建的结构不受生成器硬约束限制，被排除的比例可能很大。如果只报告分母内的成功率，会高估策略在玩家结构上的实际覆盖面。
- 【推断】玩家常搭的窄沿、高差大的结构，很可能落在"几何不可行但实际可爬"的区间。第4层需要决定：是否放宽几何检查（例如允许部分支撑过渡），或把这类结构单独成档报告。
