# 第 1 层设计：身体与抓握

状态：整体设计及下述范围修订已确认，进入第 1 层实现与自动化验证。Reach、第 0 层产物和 ProjectSettings 不修改；参数的实测结果另见验收记录。

## 1. 目标、坐标与身体参数

身体由一个躯干 Rigidbody 和左右两个手部 Rigidbody 构成，无腿、无上臂/前臂刚体。手臂抽象为肩到手中心的可伸缩连接，不模拟肘关节。先证明单手悬挂、另一手移动、交替抓握可行，再接入强化学习。

Unity 单位采用米、千克、秒、牛顿；沿用项目现有重力，不改重力设置。训练场坐标约定 x 向右、y 向上、z 向前。训练场根节点保持单位缩放、竖直朝上，可平移及绕 y 旋转；带 Rigidbody 的三个物体都直接放在训练场根节点下，不把手作为躯干 Transform 的子物体，避免父节点运动隐式拖动物理对象。

接口中的肩部位置与手目标偏移均使用躯干刚体旋转基下的米制坐标，不额外乘视觉缩放。实现向 Unity Joint.anchor/connectedAnchor 写入时必须换算缩放；固定世界接触点则基于 Rigidbody 当前物理位姿换算，不读取可能尚未同步的 Transform 位姿。实际横档向平台前方突出 0.20 m，确保最后一个横档上方的手不会进入平台侧面实体。

| 项目 | 建议初值 | 理由 |
| --- | --- | --- |
| 躯干外形 | BoxCollider，宽 0.60 × 高 0.80 × 厚 0.35 m | 对称、接触和惯量易检查；此阶段不追求人体比例 |
| 躯干质量 | 10 kg | 与单手 10:1 的质量比仍需关注，但远小于极端的数百倍比值 |
| 手部外形 | SphereCollider，半径 0.10 m | 不依赖手掌朝向，减少棱角卡住和旋转对抓握的影响 |
| 每手质量 | 1 kg | 两手均为真实动态物体，运动反作用不能忽略 |
| 总质量 | 12 kg | 包含摆动中的自由手 |
| 左肩锚点 | 躯干局部坐标 (-0.30, +0.28, 0) m | 靠近躯干上部外侧 |
| 右肩锚点 | 躯干局部坐标 (+0.30, +0.28, 0) m | 左右对称，肩宽 0.60 m |

两个肩部 Transform 只是躯干上的几何锚点，没有额外 Rigidbody。身体碰撞对：躯干与自己左右手默认不互撞，可通过连接关节的碰撞选项或逐对 IgnoreCollision 实现；手与环境、躯干与环境正常碰撞。左右手不允许同时占用同一个小抓握槽，避免重叠后产生冲量。以上均不修改项目层碰撞矩阵。

## 2. 重量、单手支撑与最小有效动作

### 2.1 静态与动态预算

以现有重力模长 g = 9.81 m/s² 计算：

W = (10 + 1 + 1) × 9.81 = **117.72 N**。

用总重量估算支撑臂负担是保守处理；实际固定在抓点上的那只手，其自重可直接由抓握关节承担，但不据此削减安全余量。

定义支撑臂相对竖直方向夹角为 θ。只在初始可解任务中保证 θ ≤ 45°，不要将几乎水平的手臂视作同样可支撑的姿态。忽略其他支撑时，静态张力近似为 T = W / cosθ。

| 工况 | 所需单臂拉力 | 占 450 N 的比例 |
| --- | ---: | ---: |
| 竖直、单手支撑总重量 | 117.72 N | 0.262 |
| 单手支撑，θ = 45° | 166.48 N | 0.370 |
| θ = 45°，另给自由手反作用留 40 N、全身向上加速度留 1.5 m/s² | (117.72 + 40 + 12×1.5) / cos45° = **248.51 N** | **0.552** |

最后一行保守地把自由手反作用全计入不利的竖直方向。450 N 在 45° 时可提供约 318.20 N 的竖直分量；扣除上述 175.72 N 的需求，还余 **142.48 N**，约为需求的 **81%**。因此单手保持悬挂时，另一只手以不超过 40 N 的驱动力寻找下一抓点，不必依赖双手同时支撑。自由手自身也受重力；40 N 并非全部用于加速，竖直运动时可用净力约 30.19 N。

该余量不覆盖任意冲击、动态抓点塌落、持续撞墙、任意手臂角度。初期抓点布局需满足：自由手到目标的肩距 ≤ 0.85 m，支撑臂 θ ≤ 45°，身体与下一抓点之间没有必须穿越的障碍。先采用相邻抓点高度差 0.20–0.30 m、横向间距 0.30–0.50 m，并以实际左右肩位姿检查可达性；不能只凭抓点间距判定可达。

### 2.2 “把自己拉起来”对应什么动作

对外提供归一化努力值 u ∈ [0,1]，令支撑手主动合力上限为 **u × 450 N**。手已固定在抓点，控制器将其相对肩部的目标适当缩短，执行器试图把手向肩部拉，反作用力把躯干向抓点拉。

- 理想竖直起拉阈值：u_min = W / 450 = **0.262**；只有严格超过阈值，才有正的向上加速度。
- θ = 45° 的静态起拉阈值：u_min ≈ **0.370**。
- 上述自由手移动与抬升预算：u_min ≈ **0.552**；初始脚本动作采用 u = **0.70**，而不是一开始就满输出。

因此有效动作不挤在接近 1 的狭小区间。但 **u 是力上限，不是实际力保证**：若目标误差很小，PD 请求力可能低于这个上限。拟采用 Kp = 900 N/m、Kd = 70 N·s/m；静止时产生 248.51 N 需要约 0.276 m 的沿拉力方向误差，必须保证目标缩短量足够且仍在可达空间内。例如将 0.80 m 的支撑距离目标缩短到约 0.50 m，再逐步更新，不能把目标设在手当前位置却期待上升。

悬空测试不应包含身体顶住墙壁时的额外接触摩擦，否则上述重量阈值不再完整。实现后要在无墙接触的标准夹具中测试 u = 0.10、0.25、0.35、0.50、0.70，并记录真实力、肩部高度与速度。低于阈值不能主动抬升是预期行为；不要把“最小有效动作”误解为任意微小动作都必须抗重力。所有输出合力和辅助力都必须计入预算，不能额外添加未计费的重力补偿。

## 3. 手臂连接与驱动选择

### 3.1 首选方案：距离限制关节 + 显式限幅的内部 PD 力

每只手有一个 ConfigurableJoint 连接躯干 Rigidbody：手侧 anchor 为球心，躯干侧 connectedAnchor 为对应肩部局部坐标，关闭自动锚点配置。三个线性轴均 Limited，公共线性距离限制 L = 0.90 m；角向全部 Free。目标是肩—手距离上限，不是把三个坐标分别做成允许 √3×L 对角距离的盒子。实际版本中的径向限制行为必须用对角方向夹具确认。

内建 x/y/z Drive 和角 Drive 初始全部关闭。驱动力由身体组件在 FixedUpdate 内统一计算：

F_raw = Kp × (手目标位置 − 手位置) + Kd × (目标速度 − 手速度)

F_cmd = ClampMagnitude(F_raw, u × F_stage)

F_stage 在抓握时为 450 N，自由手时为 40 N；目标移动速度限制为 1.5 m/s，努力值上升时间初值为 0.15 s，避免抓住瞬间从 40 N 跳到 450 N。计算使用一致的世界坐标，局部目标先明确转换；相对目标速度包含肩锚点因躯干平移、旋转而产生的速度。

在手刚体施加 F_cmd，在躯干侧施加等大反向力，使用 ForceMode.Force，不直接改速度或 Transform。只给手施力而不向躯干传递反作用，会把“肌肉”错误地做成外部推进器。对于非径向的力，还需核对这对分离作用点形成的力偶：将其反作用扭矩计入躯干，保证自由飞行、无接触时整个身体的角动量也不会凭空增加。第 1 层仍补偿非径向主动力的力偶；独立肩部扭矩预算推迟到第 2 层。纯径向拉力不产生该附加力偶。

选择理由：合力向量长度有一个直接、可测的 450 N 上限，控制器接口不与三个轴的求解器细节耦合；可以单独验证正反作用及最小有效动作。代价是显式 PD 比隐式关节驱动更依赖时间步长，不能用极大的 Kp 硬拉。保留现有约 0.02 s 步长，先以低速和有限目标误差验证，不改全局时间或物理设置。

### 3.2 maximumForce 的真实含义与备选方案

若后续改为 ConfigurableJoint 的内建位置 Drive，PhysX 根据位置/速度误差及 spring/damper 求解驱动力，`JointDrive.maximumForce` 为该驱动设置力限制。它不是位置误差上限，也不是“越大越精确”的免费参数。Unity 6 提供 `useAcceleration` 区分相关驱动模式；本设计的力预算以牛顿为准，备选方案须使用力驱动并验证实际输出。[Unity 驱动说明](https://docs.unity.com/en-us/engine/6000.7/manual/physics-section/physics-overview/joints-section/create-configurable-joint/configurable-joints-driving-forces)、[Unity 6000.3 关节参考](https://docs.unity.com/en-us/engine/6000.3/manual/physics-section/physics-overview/joints-section/create-configurable-joint/class-configurable-joint)。

三个轴各设 maximumForce = 450，不能保证合力 ≤ 450；轴向同时饱和时可能达到约 779 N。保守办法是每轴最多 450/√3 ≈ 259.81 N，但这样单轴起拉阈值要重新按 259.81 N 计算，不能继续使用上节的 450 N 向量预算。另一办法是为三个轴分配共同的向量预算，并逐轴验证。故第 1 层不同时启用内建 Drive 和自定义 PD，以免双重施力。

### 3.3 主动力、臂长限制反力与结构强度必须分开

**450 N 是主动执行器合力上限；距离限制和接触约束不受这个限幅器或 Drive.maximumForce 自动约束。**到达最大臂长时，关节可能被动承受悬挂重量；这不等于电机在主动抬升。

第 1 层肩部距离连接不可断裂：breakForce 与 breakTorque 均为 Infinity，仅记录峰值约束负载。直臂到达距离上限后的被动悬挂是合法状态，不因被动负载超过主动电机预算而松手或判失败。450 N 仅约束主动电机合力。被动反力不保证受该上限限制；不得把峰值约束负载误报为实际肌肉输出。抓握关节仍保持 900 N / 90 N·m 断裂。

PhysX 文档明确区分约束受力与驱动受力；驱动力不应被假定完整包含在关节的受力报告或断裂判断中。因此不能只看 currentForce 或只设 breakForce，就宣称主动驱动已经被正确限幅。实现时需分别验证 Unity 6000.3 的报告行为及施力日志。[PhysX 关节文档：Actuation、Force Reporting、Breakage](https://nvidia-omniverse.github.io/PhysX/physx/5.4.1/docs/Joints.html)。

## 4. 躯干旋转约束

初期默认冻结躯干世界 x、z 旋转，允许 y 旋转；不冻结平移。这样先隔离俯仰、侧翻带来的复杂性，仍保留转向。手是球体，角自由度不影响接触几何，默认不冻结手的旋转，避免与动态物体上的 FixedJoint 方向约束冲突。

对外配置 `LockRotationX`、`LockRotationY`、`LockRotationZ`，默认 true、false、true；在重置时应用，回合中不突然切换。后续可按 x、z 逐轴解锁并重新验证，不把“开关”藏在控制器里。冻结轴会引入外部约束反力矩，所以早期结果不能作为自由旋转身体的平衡能力证明。动态可抓取物体的初期任务也要控制其转动速度，不能让它与被冻结的躯干形成强制扭转的闭环。

## 5. 抓握准入、连接与释放

### 5.1 有抓取意图不等于可以吸附

`SetGrab(hand, true)` 仅表示请求。满足以下全部条件才允许建立抓握：

1. 有实际手部 Collider 接触，或数值容差内的接触（表面间隙 ≤ 0.01 m）；半径稍大的 Trigger 只收集候选，不单独授权抓握。不得从远处直接创建关节把手拉到表面。
2. 候选在明确的 Grabbable 层，且具有环境侧可抓取描述；同属本训练场、不是身体自己、不是另一只手，不允许跨训练场连接。
3. 合法部位必须是上表面或由上表面构成的边缘，不接受单纯的竖直面。
4. 接触相对速度初值 ≤ 1.0 m/s，目标角速度初值 ≤ 1 rad/s；在冷却期外，该抓握槽没有被另一手占用。

### 5.2 上表面与边缘判定

接触法线统一成“从环境表面朝外”的方向，不直接信任不同回调对象的 normal 符号。上表面要求 normal·训练场 up ≥ **cos45° ≈ 0.707**。此外验证手中心位于该表面外侧，避免从下方穿透后误抓。法线与 up 的比较在同一坐标系中进行。

边缘不能简化为“竖直面靠近顶部就能抓”：

- BoxCollider 不依赖人工标记：由 center、size、当前缩放与旋转计算六个面的朝外法线，选择与训练场 up 点积最大的面作为当前顶面；点积需满足 0.707 门槛。由该面矩形自动导出四条顶边，边带初值 0.05 m。
- 必须能在触点附近找到真实、可达、法线合格的顶面；从上方作短距离探测验证顶面位置，接触球也必须在顶边的几何接触范围内。探测范围受手半径和 0.01 m 接触容差限制，不穿墙找隐藏顶面。
- 一般 Mesh 初期要求作者标记可抓顶面/边缘；不使用 Renderer.bounds 的“最高 y”代替真实几何面。
- Box 倾倒后重新计算当前顶面，原侧面可成为新的上表面；不把固定的局部 +y 永久视为顶面。非基本形状才保留人工标记。第 1 层只抓静态 Collider；有 Rigidbody 的动态和运动学候选明确拒绝。

### 5.3 动态 FixedJoint

在手 Rigidbody 上动态创建一个抓握 FixedJoint，肩部连接仍然保留。手不改为 Kinematic，不修改父节点、不瞬移、不将速度强制清零。创建时两端锚点表示同一世界接触点，关闭自动锚点：

| 表面类型 | connectedBody 与锚点处理 |
| --- | --- |
| 静态 Collider、无 Rigidbody | connectedBody = null，固定到世界；hand.anchor 为手局部接触点，connectedAnchor 为世界接触点。此静态对象在抓握期间不得通过 Transform 移动 |
| 动态 Collider | connectedBody 为 collider.attachedRigidbody，包括其子 Collider；connectedAnchor 为该 Rigidbody 局部接触点，hand.anchor 为手局部接触点。双方保留真实质量、重力与运动 |
| Kinematic 移动抓点 | 接到其 Rigidbody，但属于可外部供能的运动边界；初期单独测试，不能混入自由动态物体的验证结果 |

`connectedBody = null` 的世界固定语义及 FixedJoint 的约束/断裂属性参见 [Unity Joint API](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/joint)、[Unity ConfigurableJoint 参考](https://docs.unity.com/en-us/engine/6000.3/manual/physics-section/physics-overview/joints-section/create-configurable-joint/class-configurable-joint)。

抓握关节初值：breakForce = **900 N**、breakTorque = **90 N·m**。它比主动执行器力预算强，避免普通约 166–249 N 的单臂负载频繁误断，又保留冲击或拖拽重物时的失败路径。它不意味着可以用 900 N 的手臂拉力。动态抓点初期至少采用 10 kg、尺寸 0.4 m 以上、可稳定受载的物体；悬浮动态物体不是固定世界支点，抓住它后双方一起下落完全符合预期。

释放或断裂后进入 **0.20 s 冷却**；断裂后建议 **0.30 s**。持续保持 true 不应导致断裂后一冷却结束就自动吸回：必须先收到 false，再收到新的 true 请求。释放即时停止该抓握关系，但肩部连接继续存在。处理 Destroy 的延迟：先在逻辑上标记禁用、解除连接并清理占用，防止同一物理步生成两个抓握关节。断裂事件必须辨别是肩部连接还是抓握连接，分别报告原因。

初期双手不能同时锁定同一个小槽；对两个不同的动态物体形成的闭环连接，先记录为专门的稳定性测试，不默认属于第一个教学任务。

## 6. 显式 Physics Material

所有有 Collider 的新身体及环境物体均显式分配 Physics Material，包括 Trigger 感知体（虽然 Trigger 不提供摩擦承载）。仅视觉对象无须材质。创建第 1 层专用资源，不覆盖第 0 层 ReachLowFriction。

| 对象 | 静摩擦 | 动摩擦 | Friction Combine | Bounciness / Bounce Combine |
| --- | ---: | ---: | --- | --- |
| 躯干、左右手实体 Collider | 0.15 | 0.15 | Average | 0 / Average |
| 可抓取台面、边缘、动态抓点 | 0.15 | 0.15 | Average | 0 / Average |
| 地面、普通障碍、保护平台 | 0.15 | 0.15 | Average | 0 / Average |
| 仅候选感知用 Trigger | 0.15 | 0.15 | Average | 0 / Average |

统一值使组合后的摩擦仍为 0.15，不依赖某个物体误用默认值。可靠悬挂由通过准入的抓握关节提供，不靠把手材质摩擦提高到不合理值。0.15 是独立于 Reach 的第 1 层初值，后续必须用手部平面小动作测试确认阈值：1 kg 手在水平面上约需 1.47 N 的切向力；自由手 40 N 上限对应的单轴动作阈值约 0.037。在空中向上移动自由手，仅克服自重就需约 9.81/40 = **0.245** 的努力值，不能只验证水平滑动。

## 7. 身体与控制器接口

身体组件是唯一可以施力、改变肩部驱动、创建/销毁抓握关节及执行重置的主体。手动控制器、脚本控制器、未来 ML-Agents 都只能提交身体命令或读取快照，不能直接访问 Rigidbody、Joint 或 Transform 进行修改。当前已实现脚本控制器，手动控制器将独立提交；本设计不预先确定 ML-Agents 的观察与奖励。

### 7.1 命令合同（设计签名，不是代码实现）

| 方法 | 语义 |
| --- | --- |
| SetHandTarget(handId, offsetFromShoulderBodyLocal, effort01) | 目标是相对对应肩部的躯干局部偏移，单位 m；努力值 [0,1]；身体验证、投影到合法目标空间、限速，并转换到物理世界计算 |
| SetGrab(handId, requested) | 提交抓握/释放意图；返回请求状态，不承诺一定抓住；实际结果由状态与事件确认 |
| GetBodyState() | 原子快照：训练场局部位置/旋转、局部线/角速度、总质量、已抓手数、有效旋转约束、是否失败 |
| GetHandState(handId) | 训练场局部位姿/速度、肩部局部偏移、臂长/比例、目标及裁剪标记、努力值/实际命令力、自由/候选/抓握/冷却/断裂状态、抓点 ID、冷却剩余时间 |
| GetGripCandidate(handId) | 候选 ID、接触点/法线（训练场坐标）、表面分类、相对速度、准入结果及拒绝原因 |
| GetLoadState(handId) | 主动命令力与约束反力分别报告，注明各自坐标、采样时刻和来源；不把 currentForce 当完整肌肉力 |
| ResetBody(resetSpecification) | 仅由回合管理器调用；清除抓握、占用、命令、冷却与缓存，再重置三个刚体姿态及线/角速度；最后恢复合法肩部连接并唤醒 |

读接口返回值数据，不暴露可写物理组件引用。所有局部坐标字段在名字和文档中注明属于 Arena、Torso 还是抓点刚体；世界坐标仅在物理适配层内部使用。两个手目标在同一个物理步批量提交，FixedUpdate 消费最新完整命令，重置期间不消费旧命令。每个身体同一时刻只有一个控制器拥有写权限。

建议事件：GrabSucceeded、GrabRejected（含原因）、Released、GripBroken、ArmBroken、Overloaded、ResetCompleted。所有事件含 handId、arenaId、物理步号，支持 16 场地定位问题。

配置参数至少包括：尺寸/质量、肩部位置、臂长、力/扭矩上限、Kp/Kd、目标/努力值变化速度、旋转轴锁、抓握法线阈值、间隙/速度阈值、断裂参数和冷却时间。配置在创建或重置时生效；不能由未来策略随意增大自己的物理能力。

## 8. 风险与预防

| 风险 | 预防与诊断 |
| --- | --- |
| 肩部锚点错误、世界/局部混用导致关节爆炸 | Gizmo 显示两端锚点和臂长球；在平移、绕 y 旋转的训练场重复验证；初始手不超过最大距离 |
| 固定手 + 肩部目标瞬跳，产生巨大冲量 | 目标限速、努力值渐变、有限合力、接触速度门槛；抓住时以当前相对位置初始化目标，不瞬移到预设点 |
| PD 抖动或数值发散 | 从 Kp=900、Kd=70 起步；记录力饱和率、速度和长度误差；只调一个变量；必要时调整各刚体 solverIterations/solverVelocityIterations，不改全局 Physics 参数 |
| 质量比/双手闭环导致求解困难 | 当前比例 10:1；初期双手只接静态、相容抓点；massScale/connectedMassScale 保持 1，不用非物理质量缩放掩盖问题 |
| 硬限制和碰撞反力绕过主动拉力预算 | 区分主动力/约束力；第 1 层肩部不可断裂、仅记录被动峰值；不声称 maximumForce 限制一切受力 |
| 穿透或高速漏接触 | 手和躯干采用合适的连续碰撞模式，限制目标速度；薄板先用厚度 ≥0.10 m 的碰撞体；即使有 Trigger 也做接触与几何验证，不能假定 CCD 能保证一切抓握事件 |
| 抓在竖直墙面或下表面 | 层只是第一关；再验证朝外法线、顶面探测、标记边缘、手中心所在侧；拒绝仅靠大 Trigger 的吸附 |
| 动态物体被意外钉到世界 | 有 attachedRigidbody 必须连接它；仅真正静态物体允许 connectedBody=null；移动平台必须有 Rigidbody |
| 释放后立即吸回、延迟销毁导致双关节 | 释放/断裂冷却、false→true 重新武装、逻辑先失效再清理；每手最多一个有效抓握连接 |
| 手臂力成为无接触飞行推进器 | 总体质心/动量测试；等反作用及力偶预算；所有辅助力计费；空中不能靠左右手运动持续抬升质心 |
| 冻结旋转制造不现实的稳定性 | 约束显式可配置，报告开启的轴；不把初期通过视作无约束身体平衡已通过 |
| 模型“作弊”依赖默认摩擦或无限抓力 | 所有 Collider 显式材质；有限主动驱动与抓握断裂阈值；日志检查配置，不允许控制器直接改物理参数 |
| 重置跨回合残留连接或速度 | 统一 ResetBody；清除世界固定和动态固定连接、占用和缓存，三个刚体均清零线/角速度；检查重复重置幂等性 |

## 9. 实现后、强化学习前的验收顺序

本任务执行第 1、3、4、5（仅静态）项，并增加自由手静止 5 秒抖动、双手翻上平台及 1/16 场地脚本控制测试。其他项目按范围推迟。

1. **几何与材质**：检查三刚体尺寸、质量、肩锚、非零显式摩擦；验证轴向和对角伸展不超过 0.90 m 加 0.02 m 的数值容差。持续超差应失败，不通过 Transform 拉回身体。
2. **无接触守恒**：自由下落时移动两手，质心轨迹应符合重力；关闭躯干旋转锁的专用夹具检查内部动作不会凭空注入角动量。
3. **最小动作**：在标准单手悬挂夹具中分档输入努力值；分别验证 θ=0°、45°，同时记录 PD 请求、限幅后力、连接反力、位移和速度。要求 u=0.70 能受控抬升，不能只确认 u=1 能工作；再检查停止/反向指令后的过冲。
4. **单手保持与自由手够点**：同一支撑手保持 5 s，自由手在其 40 N 预算内够到合法下一抓点；检查支撑丢失、超载、臂长误差与身体姿态。
5. **抓握正反例**：上表面/合法边缘可抓，竖直面/下表面/非抓取层/跨场地不可抓；高相对速度拒绝；静态和动态抓点分别验证；过载和冷却可观察。
6. **脚本控制闭环**：只通过身体接口完成左右交替的至少 3 次换手；先 1 场地，再 16 个分散场地全部通过。记录每场地结果，不能只看总成功率。
7. **手动控制复核**：通过相同接口操作目标、努力值与抓握，验证停止和松手反馈；不另走特殊施力路径。
8. **最后才接训练**：可解性与物理边界通过后再设计 ML-Agents 的动作、观察和奖励。失败先只读诊断并汇报证据，确认后单变量修改，使用新 run-id；Reach 与 layer0-done 保持原样。

## 10. 当前确认的范围

保留 12 kg 身体、0.90 m 臂长、450 N 支撑/40 N 自由手预算、距离限制关节和限幅 PD，以及躯干默认冻结 x/z 旋转。肩部连接不可断裂，抓握可断裂，允许固定手产生双向推/拉力。

第 1 层仅包含静态 Box 横档、静态顶部平台、自动顶面/顶边判定、基本身体查询与命令、Gizmo/诊断日志、脚本控制器和本轮自动化测试。动态抓点、运动学抓点、一般双手闭环稳定性专项、肩部扭矩预算、解锁旋转的角动量专项测试、完整事件系统和 GetLoadState 细节推迟到第 2 层。上述早期章节中的相关接口与风险讨论为未来设计，不属于本轮交付。双手连接同一静态顶部平台的撑起动作是本层必要特例，不实现任意动态闭环系统。非径向内力的反作用力偶补偿仍必须实现。

## 11. 翻上平台

PD 不是只允许拉伸的绳索电机：手固定后，目标相对肩部位置可以从肩上方连续移到肩下方，从而对固定手施加向下的力、向躯干施加向上的反作用力，实现撑起。主动推力与拉力共用同一个 450 N 向量上限，不添加额外抬升力。

测试平台顶面 y=2.00 m，前缘 z=0，躯干宽/高/厚仍为 0.60/0.80/0.35 m。动作阶段：沿交替横档上升并完成至少三次左右换手；双手各抓顶部前缘不同位置；保持躯干在前缘外侧，先将躯干中心抬到 y≈2.48 m，使底面越过平台；随后保持双手固定，受控向内移动躯干到 z≈0.55 m，落稳或保持受控支撑。不得移动躯干 Transform、忽略平台碰撞或在到达时瞬移。

目标区域是训练场局部的躯干中心区域：中心 (0,2.60,0.60) m，尺寸 (0.80,0.40,0.60) m，即 x∈[-0.40,0.40]、y∈[2.40,2.80]、z∈[0.30,0.90]。到达要求中心在区域内连续 0.30 s，且躯干线速度 <0.50 m/s。目标区域仅检测躯干中心，不以手接触触发成功；平台实体碰撞保持开启。
