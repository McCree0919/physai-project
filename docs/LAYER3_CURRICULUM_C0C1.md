# 第3层：课程C0+C1的评估（2026-11-11）

【数据】是有测量支持的结论，【推断】是解释，附带如何验证。训练设置见[LAYER3_DESIGN.md](LAYER3_DESIGN.md) §17，完成标准见§16。

## 1. 结论摘要

- 【数据】在训练用两级台阶上，两个C0+C1 checkpoint都是200/200成功，达到§16回归标准（≥90%），与§6修复后的基准（99.5%、100%）相当。
- 【数据】在27个保留的C1验证结构上：
  - 课程两个种子为99.8%和100%；
  - 同种子的高度奖励基线只有5.6%和60.7%；
  - 每个结构上，课程都不低于基线。
- 【数据】在v2 Easy评估集上，课程为78.3%（s2026）和100%（s2027），基线为13.1%和66.5%。
  - s2026在全部13个"有一级高度≥0.95m"的结构上都是0/20，其余47个都是20/20。
  - 按§16，s2027达到Easy标准，s2026没有达到（均值<80%，区间下限66.7%<70%）。
- 【数据】C1验证集的27个结构，最大一级高度全是0.5m。所以它没有检验高台阶，s2026的这个缺口在验证集上看不出来。
  - C1训练池中，高台阶结构只占7/254。
- 前瞻探测（Standard、Hard，不是本轮的考核项）：
  - Standard：s2027为64.9%（区间54.7–75.1%），已经达到§16的Standard线；s2026为34.5%。
  - Hard：两个种子都远低于标准，s2027为23.8%，s2026为0.7%。
- 【数据】严格对照（§8）：在修复后的环境中只训练两级台阶800万步，C1验证为71.1%和42.6%，v2 Easy为63.2%和43.9%。同种子下，课程高出15–57个百分点，区间都不包含0，逐结构没有一个是对照更好。
- 【推断】课程带来的提升主要是"新结构上的第二级"。基线在新结构上大多能上第一级，但上不了第二级。高台阶、3层以上和总高度>2m，是C2、C3要解决的主要缺口。

## 2. 评估协议

- **运行环境**：Player build `Builds/ClimbCurriculum/Climb.exe`，即§17.5中构建的版本。
  - 每次运行前，按`results/climb-curriculum-c0c1/player-sha256.txt`逐个核对173个文件的sha256。
  - 没有修改C#，也没有重新构建。
- **策略**：ONNX的确定性输出（`deterministic_continuous_actions`、`deterministic_discrete_actions`），在Python端推理，单线程。
  - 环境参数与训练相同：`target_mode`=0，高度奖励0.2/0.2，`spawn_seed`=0。
- **起点**：全部是地面起点。
  - 不传入状态库，所以不可能有示范起点；分析时也核对了每个回合的`spawn`=ground。
  - 地面起点与训练一致：场景自己的出生姿态，手在z=−0.05，见§17.5。
- **结构如何放入场地**：
  - 两级台阶用场景自带的结构，不传`--climb-curriculum`。
  - 其他集合各写一个单阶段的评估池文件（`twoStepShare`=0），由`ClimbCurriculum.Load`核对每个结构的sha256。每回合从池中均匀抽一个结构，与训练时换结构的方式相同。
- **取样规则**：
  - 两级台阶：取最先完成的200回合（16个场地），与§6相同。
  - 其他集合：每个结构取按开始时间最早的20回合。一个回合的开始时间，是同一场地上一回合的结束时间。等所有入选回合都结束后才停止，这样耗时长的失败回合不会被少取。
  - 池外结构的回合数为0，所有运行都是如此。
- **模型**：

  | 标签 | 文件 | 训练 |
  |---|---|---|
  | c0c1_s2026 | `results/climb_curriculum_c0c1_s2026/Climb/Climb-8000051.onnx` | C0 300万步，然后C1 500万步 |
  | c0c1_s2027 | `results/climb_curriculum_c0c1_s2027/Climb/Climb-8000081.onnx` | 同上 |
  | height_s2026_5M | `results/climb_height_shaping_s2026/Climb/Climb-5000009.onnx` | 只训练两级台阶，ResetBody修复前 |
  | height_s2027_5M | `results/climb_height_shaping_s2027/Climb/Climb-5000007.onnx` | 同上 |

  课程模型用的是最终checkpoint，没有按评估结果挑选。
- **统计**：
  - 以结构为单位：s_i等于该结构20回合的成功率；集合的成绩是mean(s_i)，每个结构权重相同。
  - 95%区间用簇bootstrap：整簇重采样10000次，取百分位。
  - C1验证集有27个结构，分属17个簇（§17.2）。v2评估集每个结构自成一簇（[LAYER3_GENERATOR_V2.md](LAYER3_GENERATOR_V2.md) §4.2）。
- **几何检查**：只在通过`BoxStackFeasibility.Check`的结构上计算。
  - 【数据】C1验证27/27通过，v2评估集180/180通过，所以没有排除任何结构（被排除的数量为0）。
- **脚本控制器参考**：每个结构1次运行，来自已有的审计：
  - C1验证：[curriculum-audit](data/curriculum-audit/audit.csv)；
  - v2：[feasibility-audit](data/feasibility-audit/audit.csv)。
  - 它不是严格的上限：在Easy和C1验证上，策略超过了它（§4）。
- **数据**：[docs/data/curriculum-c0c1-eval/](data/curriculum-c0c1-eval/)
  - `summary.json`；
  - `structures.csv`：每个模型×结构一行，含形状特征；
  - `episodes.csv`：全部回合。
  - 脚本为`scripts/run_curriculum_eval.py`、`scripts/analyze_curriculum_eval.py`；原始运行在`results/curriculum-c0c1-eval/`。

## 4. 失败分类

### 4.1 失败阶段

阶段按回合中达到的躯干高度划分：一级是躯干≥0.45m，二级是躯干≥0.95m，这是`ClimberAgent`中的绝对高度阈值。
- 对3层以上的结构，或第一级就很高的结构，"二级"并不等于第二层箱子。
- 下表只统计失败的回合。

| 集合 / 模型 | 失败回合 | 未到一级 | 一级未到二级 | 到二级未完成 | 结束原因 |
|---|---|---|---|---|---|
| C1验证 / c0c1_s2026 | 1 | 0 | 0 | 1 | Timeout 1 |
| C1验证 / height_s2026 | 510 | 0 | 484 | 26 | Timeout 503，Fall 6，UnrecoverableGrip 1 |
| C1验证 / height_s2027 | 212 | 3 | 76 | 133 | Timeout 212 |

- 【数据】失败几乎都是Timeout，Fall和出界每档≤0.7%。策略不会摔下来，而是停在某一级上，没有找到继续向上的动作。
- 【数据】基线在新结构上的主要失败阶段是"一级未到二级"。例如height_s2026在C1验证上，失败中484/510属于这一阶段。课程模型在C1验证上几乎没有失败。
- 【数据】同一结构的20个回合大多结果相同，例如c0c1_s2026在Standard上，55/60个结构是0/20或20/20。
  - 【推断】出生姿态固定，策略确定，物理接近确定，所以20个回合大体是同一条轨迹的重复。按结构统计、按簇给区间是必要的，不能把回合当作独立样本。

- 【数据】Standard、Hard上的成功率，随层数、总高度和maxRise的增加而下降。s2027在Hard上能完成的，基本限于maxRise<0.6m、总高<2m的结构。
- 【数据】策略与脚本控制器逐结构对照（策略以s_i≥0.5算作完成）：
  - Easy / c0c1_s2027：60个都完成，其中19个是脚本没有完成的。
  - Hard / c0c1_s2027：完成12个，其中6个是脚本没有完成的。另有34个结构脚本完成了，而策略没有。
  - 【推断】脚本的路线是固定的，与策略的失败模式不同。用它作"参考上限"只在汇总意义上成立，不能逐结构当作可解性的证明。

## 5. 解释与对C2、C3的参考（【推断】）

1. **课程带来的是泛化，不只是原有能力。**
   - 依据：同种子配对时，课程在每个结构上都不低于基线；基线在新结构上失败在第二级；课程训练的唯一变量是结构分布（§17.3）。
   - 但基线是在ResetBody修复前训练的，步数也不同（500万对800万）。所以差值不能全部归因于课程，只能说课程训练结束时的能力明显更强。
   - 若要严格区分：用相同的800万步，在修复后的环境中，只训练两级台阶，作为对照。这次没有做。
   - **更正（2026-11-11）**：严格对照已经完成，见§8。课程在两个保留集、两个种子上都明显高于对照，逐结构没有反例。
2. **种子差异很大。**
   - s2027在C0阶段就已经会爬两级台阶（§17训练日志：C0结束前地面成功4313/4787），也学会了高台阶。
   - s2026在C0阶段几乎没有学会第二级，最终在高台阶上完全失败。
   - 两个种子太少，看不出哪种情况更典型。
3. **高台阶在训练分布中太少。** s2026的缺口与C1池中高台阶占2.8%直接对应。
   - C2/C3的候选方向是提高高台阶的比例（只是一个单变量改动的建议，需要你决定）。
   - 例如按maxRise分层抽样，或者在C2中包含Standard训练池的高台阶结构。
4. **Standard/Hard的主要缺口**：3层以上、总高超过2m，并且"未到一级"的比例很高（Hard中38–56%的回合）。
   - Hard的第一级多数也是0.5m，为什么连一级都很难上，原因还没有诊断。
   - 可能的方向是更高结构的视野、局部几何观察的范围或落脚空间。需要先做只读诊断。
5. **评估集的覆盖**：
   - 课程验证集应当覆盖训练分布中的关键特征，至少包括maxRise分层。下一阶段冻结课程池时，建议按特征分层后再按簇划分。
   - 这次的C1验证集已经冻结并用过，不重新划分。

### 6.1 先说明用到的定义

- **"一级"**：`ClimberAgent`中，躯干静止支撑在一个顶面高度≥0.45m的表面上，持续0.3s。所以"未到一级"等于"从没站上任何离地的台面"。
- **有效第一级**：几何检查路线上第一个可站立表面的顶面高度（`feasibility.route[1]`）。
  - 【数据】它和`maxRise`特征不是一回事。Hard中，有26个结构的第一级由两个0.5m箱叠成：下面的箱顶被上面的箱几乎盖住（可站深度0），上面的箱只后退0.10–0.30m。所以真正要站上的第一个台面在1.0m，而`maxRise`报的是0.5m。
- **出生点**：躯干在z=−0.4，双手在z=−0.05。

### 6.3 判断

| 候选原因 | 结论 | 依据 |
|---|---|---|
| 踏面过窄 | **不是主因**（【数据】） | 失败组与成功组的深度、宽度相近；Easy约1.0m组深度0.51m，s2026仍是20/20到一级。 |
| 够不到第一个顶边（距离） | **不是主因**（【数据】为主） | 出生距离各组相同。1.0m顶边在出生时双手的高度附近（手y=0.95/1.15）。几何检查判定可达，脚本控制器在这一组完成81%。 |
| 台阶过高（有效第一级约1.0m） | **主要相关因素**（【数据】） | Hard一级率：0.5m组0.81–0.82，约1.0m组0.10（s2026）、0.45（s2027）。 |
| 其他：结构上下文 | **很可能参与**（【推断】） | 同样是约1.0m的单个高箱：在Easy中两个种子都是20/20到一级，在Hard中只有0.00/0.17。几何上的差别是周围更多箱体：外露顶边10.7 vs 5.4，Hard有侧岛和更高的后续台阶。 |

- 【推断】局部几何观察（262维）在Hard中看到的是训练中没有见过的配置：周围有箱体，后面还有更高的台阶。策略在这种观察下，没有执行它在Easy高箱上能完成的上第一级动作。
  - 这个推断还没有验证：需要抓握尝试次数、被拒原因和躯干最大高度。
- **这次缺少的测量**：当前课程Player的场景中没有挂被动观察器`ClimbDiagnosticsObserver`。所以抓握尝试次数、被拒原因、躯干最大高度这三项，在不改代码、不重新构建的条件下拿不到。现有的数据只能给出高度分段：未到0.45m、到0.45m、到0.95m。
  - 可行的补测：用现有的`ClimbDiagnosticsBuild.Build`（不改代码）从当前提交构建一个带观察器的Player，在Hard上重跑§3的协议。
  - 构建需要在主工作目录临时切换（worktree无法构建），所以要你批准。
- 对C2的含义（【推断】）：
  - 台阶高度应当按路线上的有效上升来计算，不能用`maxRise`，因为叠箱形成的1.0m台阶会被漏掉。
  - Hard的难点主要不是层数，而是1.0m的有效台阶出现在复杂的周围结构中。

**对"周围环境干扰"推断的检验（【推断】）**
- 补测支持"失败发生在接触之后"：策略能接近并抓住第一级附近的边，但在叠箱上抓错了边（低边），在单个高箱上或者拉不上去，或者上去了站不稳。
- s2026在6个外形相同的单个高箱上表现差别很大（3个几乎不离地，3个接近站上），这与"结构上下文影响行为"一致。

  - 能直接检验的对照：用同一Player和协议，在v2 Easy的13个单个高箱结构上跑观察器（每个模型约5分钟），比较抓的边、躯干高度和拉力。如果Easy中抓高边并拉上去，而Hard中同样的高箱上不是，差别才能归因到结构上下文。
  - 叠箱组的现象（抓低边）有一个更具体的解释：下面那个0.5m箱在观察中像一个熟悉的0.5m台阶。这属于"第一级的局部几何"，和"周围箱体"不是同一个因素。

### 8.4 解释

1. **课程本身有明确贡献。**（【数据】支持，前提是只有两个种子）
   - 对照与课程使用相同的修复后环境、相同步数和相同超参数，唯一的差别是训练结构分布。
   - 在两个保留集上，两个种子的课程都明显高于对照，逐结构没有反例。
   - 所以§3中"课程 vs 修复前基线"的大差值，不能只用ResetBody修复或步数来解释。
2. **高台阶能力只来自C1的高台阶结构。**（【数据】）
   - 两个对照种子在13个Easy高箱结构上都是0/20成功。s2026对照在其中97%的回合能站上高箱，但上不去后面的0.5m，和课程s2026的失败方式相同。
   - 只有课程s2027学会了高箱后的下一级。【推断】这说明高台阶后的动作必须在训练分布中出现，单靠两级台阶学不到；也支持C2提高高台阶比例的方向。
3. **在两级台阶上训练更久，泛化不一定更好。**（【推断】，涉及两个变量）
   - s2027对照（修复后，800万步）在C1验证和Easy上都低于s2027的修复前基线（500万步）：42.6% vs 60.7%，43.9% vs 66.5%。s2026方向相反（71.1% vs 5.6%）。
   - 修复和步数同时改变，加上种子差异很大，所以无法分开。可能的解释是，在单一结构上训练更久会过拟合到这个结构。这一点没有验证，也不影响第1条结论。
4. 对§5第1条的更正：§5中写"这次没有做"严格对照，现在已经做了，结论见本节第1条。
