# 第3层：身体快照与示范状态初始化设计（待审阅，未实现）

状态：仅设计。不修改身体、Agent或训练配置；用户审阅后决定是否实现。对应[LAYER3_DESIGN.md](LAYER3_DESIGN.md)第10节（示范状态初始化）。依据是当前源码：`ClimberBody.cs`、`ClimberAgent.cs`、`ClimbAcademyClock.cs`、`ClimberArenaFactory.cs`，以及本机ML-Agents包的`Runtime/DecisionRequester.cs`。

## 1. 目标与约束

- 从示范轨迹的合法中间状态开始一个训练回合，并且从这一刻起，后续物理行为应与原轨迹继续运行时一致，误差在第5节定义的容差内。
- 快照只能由身体内部恢复：新增`ClimberBody.CaptureSnapshot()`和`RestoreSnapshot()`，它们与`ResetBody`同级，属于回合管理接口。控制器和Agent的动作路径仍然只能调用`SetHandTarget`和`SetGrab`，不得直接操作Rigidbody或Joint。不能用瞬移躯干来伪造状态。
- 恢复只在回合边界进行（`OnEpisodeBegin`内，由环境管理器调用），从不在回合中途进行。
- 默认身体参数、物理材质和ProjectSettings不变。快照中记录身体配置的hash，配置不一致时拒绝恢复。

## 2. 快照内容

所有位置、方向和速度都存为**场地局部坐标**（相对场地根`transform`），因此可以在16个场地之间、平移或绕y轴旋转后的场地之间互相恢复。浮点数按IEEE位模式（`BitConverter.SingleToInt32Bits`）序列化，保证同一场地内恢复后逐位相等。

### 2.1 刚体（3个：躯干、左手、右手）

| 字段 | 说明 |
| --- | --- |
| position、rotation | 场地局部坐标；手的rotation单独存，不假设等于躯干的rotation |
| linearVelocity、angularVelocity | 场地局部坐标 |
| constraints | 躯干的旋转锁（当前锁X和Z）；手不锁 |
| isSleeping | 只记录；恢复时一律`WakeUp()`，见第4节 |

质量、阻尼、碰撞检测模式和求解器迭代次数（`ClimberArenaFactory`中的躯干10kg、手1kg、ContinuousDynamic、16/8次迭代）属于配置，不属于状态。它们计入身体配置hash，恢复时只校验，不写入。

### 2.2 肩部连接（2个ConfigurableJoint，持久存在）

手臂关节在场景生成时创建，回合之间不销毁，所以快照不重建它们。只记录并校验它们的配置：`connectedAnchor`（肩部位置）、`linearLimit`=0.9m、`contactDistance`=0.01m、各轴运动模式、`breakForce`=∞，计入身体配置hash。

PhysX关节内部累积的约束冲量（warm start）无法通过Unity读写，见第4.3节。

### 2.3 抓握关节（每只手0或1个FixedJoint）

| 字段 | 说明 |
| --- | --- |
| held | 是否抓住（`held[i] && grips[i]!=null`） |
| anchor | 手局部坐标，含`lossyScale`修正后的值，原样保存 |
| connectedAnchor | 场地局部坐标的握点。connectedBody为null，即连接到世界 |
| breakForce / breakTorque | 当前为900N / 90N·m；记录并校验 |
| gripRotation | 抓握关节创建那一刻手的rotation（场地局部坐标）。FixedJoint在创建时锁定这个相对朝向，恢复时必须用它重建，见第3节第4步 |
| capturedSurface | 被抓物体的**稳定标识**：结构文档中的object id（例如`lower`、`upper`）。不用Collider引用或`GetInstanceID()`，因为它们跨进程不稳定。恢复时按id在目标场地中解析成Collider；解析不到时拒绝恢复 |

### 2.4 身体控制器状态（`ClimberBody`私有字段）

| 字段 | 作用 | 为什么必须保存 |
| --- | --- | --- |
| requested[2] | 上一次`SetHandTarget`经球壳投影后的值 | PD滤波的目标终点 |
| targets[2] | 经1.5m/s限速滤波后、PD实际使用的目标 | **PD内部状态**，决定恢复后第一步的力 |
| effort[2] | 请求的努力值 | |
| appliedEffort[2] | 经0.15秒渐变后实际使用的努力值 | **PD内部状态**，决定力预算 |
| forces[2] | 上一个物理步的主动力 | 观察中的`CommandForce`字段读取它；不恢复的话第一帧观察会与原轨迹不同 |
| wantsGrab[2] | 当前抓握请求 | |
| armed[2] | false表示需要先输出0来重新武装 | |
| cooldown[2] | 释放或断裂后的冷却剩余时间 | |
| held[2]、captured[2] | 见2.3 | |
| peak[2]、diagnosticTime | 仅用于诊断 | 恢复，以便诊断日志连续；不影响物理 |

PD本身是显式、无记忆的：`F = clamp(900·(desired−hand) − 70·relVel, appliedEffort·预算)`。除`targets`和`appliedEffort`外没有积分项或滤波状态，所以以上字段就是PD的全部内部状态。

### 2.5 Agent任务状态（`ClimberAgent`私有字段）

| 字段 | 说明 |
| --- | --- |
| targets[2] | 命令目标q。incremental模式下是积分状态；absolute模式下只影响第一个决策之前的保持命令和观察 |
| ActiveTargetMode | 记录快照采集时的模式；恢复时与当前模式不一致则拒绝 |
| elapsed、decisions | 本回合已用的仿真时间和决策数。恢复它们，使剩余时间观察和60秒/600次决策的超时与“同一个完整任务”一致 |
| goalStable、supportStable、groundStable、brokenTime | 各判定的停留计时器 |
| supportId → supportKey | 当前支撑。源码用`GetInstanceID()`，快照改存稳定的object id，恢复时再映射 |
| highestSupport、paidSupports → paidSupportKeys | 进展奖励账本，同样改存object id。保证已经获得过的第一级进展不会再次发奖 |
| progressEvents、progressReward、level1、level2 | 进展计数和诊断标志 |
| maximumHeight | 仅用于诊断 |
| previousGrip[2] | 用于检测意外失握 |
| active | 必须为true；采集时已经终止的状态不能入库 |

奖励口径：恢复后，新回合的累计回报从0开始。快照之前已经发放的进展奖励和时间扣分不再计入本回合，但账本保证不重复发奖。

### 2.6 元数据（只用于日志，绝不进入观察）

- 快照格式版本；
- 结构文档的SHA-256与几何hash；身体配置hash；Agent接口版本（327维、6+[2,2]、目标模式）；
- 来源：轨迹id、专家版本、种子、出生扰动、采集时的物理步号；
- 阶段标签（S1/S2/S3，见第6节）；
- **采集时刻的327维观察向量**，用于恢复后的校验（第5.3节）；
- 快照处于决策周期中的第几个物理步（采集时规定为0，即决策边界）。

## 3. 恢复顺序

所有步骤都在一个`OnEpisodeBegin`调用内同步完成，中间不运行任何物理步。

1. **校验元数据**：格式版本、结构hash、身体配置hash、目标模式都必须一致；把每个object id解析为当前场地中的Collider。任何一项失败都抛异常，不静默回退到正常出生。
2. **清空当前回合**：先执行现有`ResetBody`的清理部分（释放抓握、清零冷却/请求/努力/力）。原有的`Release`用`Destroy`延迟销毁，并设`breakForce=0`让关节在下一次求解时断开。恢复路径改用`DestroyImmediate`立即移除旧FixedJoint，避免旧关节和新关节在同一帧共存，也避免旧关节断开时产生额外冲量。
3. **写入刚体位姿**：设置躯干和两只手的`position`/`rotation`（从场地局部坐标换算到世界坐标）。手先设为各自的`gripRotation`（如果抓住）或实际rotation（如果没抓）。然后`Physics.SyncTransforms()`。
4. **重建抓握关节**：对每只held的手，手的朝向此时等于`gripRotation`，在这个状态下`AddComponent<FixedJoint>()`，按快照写入`anchor`、`connectedAnchor`和断裂阈值，使关节锁定的相对朝向与原始抓握一致。然后把手的rotation改为快照中的实际rotation（刚体抓握下两者应只差数值误差），再执行一次`SyncTransforms`。
5. **写入速度**：线速度和角速度；重新应用躯干的旋转锁；对3个刚体调用`WakeUp()`。
6. **写入身体控制器状态**：2.4节的全部字段，`captured`使用第1步解析出的Collider。
7. **写入Agent任务状态**：2.5节的全部字段，supportKey和paidSupportKeys映射为当前进程的instance id。
8. **恢复后检查**（第5.1节）：穿透、臂长、抓握锚点误差、观察向量一致。失败就抛异常并记录快照id，这个快照从状态库中隔离，不重试。
9. **记录出生来源**：在回合日志中追加`spawn=snapshot:<id>:<stage>`，不进入观察。

决策相位：`DecisionRequester`按`Academy.StepCount % 5 == 0`请求决策，这个计数是全局的，恢复时无法选择。因此恢复后的前0–4个物理步，身体会按快照中的q和抓握请求保持原命令，这与现在正常出生的行为相同。快照规定在决策边界采集，往返测试中由测试代码手动对齐相位（第5.4节）。

## 4. 物理行为一致性

### 4.1 可以精确恢复的部分

第2节的刚体状态、关节配置和全部控制器/任务状态。同一场地内逐位恢复；跨场地时由于局部和世界坐标之间的变换存在浮点舍入，误差约1e-6m量级。

### 4.2 恢复后立即校验的不变量

| 检查 | 容差 | 失败时 |
| --- | --- | --- |
| 躯干和手与环境碰撞体的穿透深度（`Physics.ComputePenetration`） | ≤5mm | 拒绝 |
| 两只手的实际臂长 | ≤0.9m + 0.01m（关节极限 + contactDistance） | 拒绝 |
| held手的锚点误差：手上锚点的世界坐标与connectedAnchor之差 | ≤1mm | 拒绝 |
| held手的握点到被抓物体顶面的距离 | ≤0.111m（与抓握判定相同） | 拒绝 |
| 第一个物理步的抓握约束力 | <900N，不能在恢复后第一步就断裂 | 拒绝，并标记该快照 |
| 速度和位置均为有限值 | — | 拒绝 |
| 327维观察与快照中记录的观察 | 逐维≤1e-4（归一化值） | 同场地时拒绝；跨场地时报告超出的维度（射线恰好擦过几何边界时允许不连续，需要逐项说明） |

### 4.3 无法恢复的部分与应对

Unity不暴露PhysX的内部求解缓存：接触对的持久化信息与warm-start冲量、关节累积冲量、休眠计数器，以及broadphase中接触对的顺序。因此即使状态完全一致，恢复后的轨迹也**不保证**与原轨迹逐位一致。设计上的处理：

- **在采集时就减少依赖**：快照只取决策边界；不从“刚刚发生碰撞、接触冲量很大”的帧采样（例如手与顶面刚接触的0.04秒内，躯干撞到箱子边缘的瞬间）。具体规则由第5.4节的测试结果确定。
- **不做隐藏的落定**：默认恢复后不额外运行任何物理步。如果测试表明需要短暂落定，落定步数要写入恢复协议，计入回合时间，并且必须验证落定前后抓握状态、支撑判定和进展账本都没有变化。
- **用对照基线界定可接受的误差**（第5.4节）：恢复带来的误差必须与“系统本身对1e-6m扰动的敏感度”属于同一量级。这样可以区分接口实现错误和物理本身的混沌放大。

## 5. 计划的测试

全部是PlayMode测试，加入`ClimbLearning.Tests`和`Climber.PlayModeTests`。原有50项测试保持不变，并继续通过。

### 5.1 数据层

1. **序列化往返**：Capture → 序列化 → 反序列化 → 逐位相等，包括全部字段和元数据。
2. **同场地状态往返**：在若干代表性状态上执行Capture → Restore → Capture，两次Capture的结果逐位相等。代表性状态包括：双手自由、单手抓、双手抓、冷却中、NeedsRearm、已登第一级。
3. **跨场地往返**：在平移场地和绕y轴旋转90°的场地上恢复，全部局部字段误差≤1e-5（m、m/s、rad）。
4. **非法快照拒绝**：结构hash不一致、身体配置hash不一致、目标模式不一致、object id不存在、臂长超限、穿透超限，都必须抛异常；并且确认场地状态保持“正常出生”或明确失败，不会处于一半恢复的状态。

### 5.2 控制器与账本

5. **PD一致**：恢复后第一个物理步的主动力`forces`与原轨迹同一步的值在1e-4N以内。这个测试同时验证targets、appliedEffort和手、躯干速度的恢复。
6. **抓握语义**：恢复一个“冷却中且NeedsRearm”的快照，持续输出1不能重新抓住；输出0再输出1，必须等冷却结束后才能抓住。恢复一个held快照，第一步不断裂，锚点误差≤1mm。
7. **奖励账本**：恢复一个已登第一级的快照，停在第一级不再获得进展奖励；登上第二级时发放一次+0.1；回合累计回报从0开始。
8. **回合隔离**：快照回合之后的正常出生回合，其观察和身体状态与从未用过快照时的正常出生逐位相同。

### 5.3 观察一致性

9. 恢复后的327维观察与快照中记录的观察逐维≤1e-4（第4.2节）。

### 5.4 轨迹一致性（往返物理测试）

对每个阶段（S1/S2/S3）各取至少10个快照，测试代码手动步进物理并对齐决策相位：

- **参考轨迹T_ref**：原始轨迹从快照时刻继续运行，回放录制的动作。
- **恢复轨迹T_res**：在另一个场地或另一个回合中恢复快照，回放同样的动作。
- **空操作恢复T_noop**：在采集时刻把快照恢复到它自身，再继续运行。用于单独衡量求解缓存丢失的影响。
- **扰动基线T_eps**：恢复快照后，再把躯干位置偏移1e-6m。用于衡量系统本身的敏感度。

| 判定 | 时长 | 标准 |
| --- | --- | --- |
| 短时一致 | 50物理步（1秒，10次决策） | 躯干和手的位置误差≤1mm，速度误差≤1cm/s；离散事件（抓住/释放/断裂、冷却和重新武装、支撑id、登层标志）在同一个物理步发生 |
| 长时一致 | 250物理步（5秒） | 报告误差曲线；T_res与T_ref的误差不超过T_eps与T_ref误差的10倍；离散结局（是否抓住目标边沿、是否稳定登层）一致的快照≥95%，并逐个报告不一致的快照 |
| 闭环 | 到回合结束 | 若专家控制器支持恢复内部阶段，从快照开始用专家继续运行，比较完成与否和完成时间；否则只做开环回放，并注明 |

若短时一致不能通过，说明恢复接口存在错误，必须修复，不能放宽容差。若只有长时一致不能通过，并且T_noop同样发散，说明来源是求解缓存，按第4.3节调整采样规则，并报告。

## 6. 状态库

### 6.1 来源

- 使用专家脚本在训练结构上完整攀爬的轨迹。按设计第6.1节，专家应先适配到与学生相同的6+2动作接口，经同一条目标映射、努力值和身体路径执行。这样快照中Agent的命令目标q就是真实执行过的状态。如果暂时只能使用直接调用`SetHandTarget`的旧脚本，则令q等于身体的`requested`。这个差异要在元数据中标明，并且只能用于目标模式兼容的配置。
- 每条轨迹在每个决策边界采集候选快照，然后按下文的阶段标签和均衡规则抽样。
- 只使用训练结构。评估结构禁止进入状态库，结构hash用来检查。采集失败或恢复失败的快照会被隔离，但不能因此把结构从RL训练分布中删除。
- 失败的专家轨迹中，物理上合法的中间状态也可以使用（例如抓住第一级后滑落之前的帧）。是否入库只看第4.2节的不变量，不看脚本是否成功。

### 6.2 三个阶段

阶段由评估端的内部事件确定，只用于抽样和日志，不进入观察：

| 阶段 | 起点 | 终点 | 要覆盖的子段 |
| --- | --- | --- | --- |
| **S1 首次合法抓握** | 第一次出现合法候选之前1.0秒 | 第一次抓住第一级边沿后0.5秒 | 手接近顶边；第一次出现合法接触；刚抓住；另一只手跟进 |
| **S2 第一级拉升** | 抓住第一级边沿后0.5秒 | 在第一级上稳定支撑满0.3秒 | 下压撑起；躯干越过边沿；在顶面上落稳 |
| **S3 第一级到第二级** | 第一级稳定 | 在第二级上稳定支撑满0.3秒 | 稳定身体；释放旧握点；冷却和false→true重新武装；手伸向第二级；重新抓握；撑起 |

抽样规则：
- 每条轨迹的每个阶段按时间均匀抽样。
- 静止帧降权：躯干速度<0.05m/s且连续0.5秒没有抓握变化的帧，抽样权重设为0.2。
- 剔除第4.3节规定的高接触冲量帧。
- 每个阶段至少来自50条不同的轨迹。

### 6.3 出生比例（需要用户决定）

设计第10节原先的方案是：正常出生≥50%；示范出生中70%在第一级到第二级之间，30%在其他阶段。但诊断显示，当前策略连S1都没有学会（62%的回合从未抓住，合法接触率0.13%）。建议的初始比例是：

- 正常出生50%；
- 示范出生50%，其中**S1 35%、S2 35%、S3 30%**。

当正常出生的首次合法抓握率和第一级登层率提升后，再把示范出生的比例向S3倾斜。这个调整需要事先确定规则（例如按正常出生的第一级登层率分段切换），不能根据测试集结果临时修改。

其他规则沿用第10节：后半程示范出生比例从50%线性降到20%，最后10%的预算全部正常出生；课程推进和主评估只看正常出生的回合；中间出生的条件成功率单独报告。

## 7. 实现边界与风险

- **需要修改身体**：新增Capture和Restore接口，以及`DestroyImmediate`的恢复路径。这是第一次扩展身体的公开接口，需要用户批准。正常出生的`ResetBody`路径保持不变，第5.2节第8项测试保证这一点。
- **需要修改Agent**：supportId和paidSupports从instance id改为稳定的object id，或者在Agent内部维护两者的映射；新增任务状态的Capture和Restore。这一项会改变Agent内部的数据结构，需要在实现时证明正常出生回合的行为逐位不变（与本轮目标模式开关的复现检查方法相同）。
- **风险**：
  - FixedJoint重建时的朝向细节与Unity版本相关，必须由第5.4节的测试验证，不能只靠推断；
  - 求解缓存丢失可能使S2下压阶段这类高负载状态的长时一致性较差；
  - 专家轨迹多样性低（固定路线、单一关卡），状态库可能过窄，需要出生扰动或专家动作噪声来扩充，并报告实际轨迹数。
- 本文不涉及BC、GAIL、课程日程或奖励修改。
