# Layer 3：零样本泛化评估（不训练）

【数据】为有测量支持的结论；【推断】为未直接测量的判断，并注明如何验证。

## 1. 设置

| 项目 | 值 |
|---|---|
| 策略 | 高度新高奖励实验（[LAYER3_HEIGHT_SHAPING.md](LAYER3_HEIGHT_SHAPING.md)）两个seed的5M checkpoint：s2026 `Climb-5000009.onnx`（sha256 `6c4a8801…`）、s2027 `Climb-5000007.onnx`（`fb14299f…`）。不训练、不微调 |
| 评估集 | `structures/zero-shot-v1/`：63个结构 + `manifest.json`（sha256 `94f6f971…`）。由`ClimbZeroShot.Freeze`生成，见§1.1 |
| 对照 | 场地0为训练用两级台阶，生成方式与训练场景相同（`BoxStackGenerator.Smoke(true)`） |
| 协议 | 地面出生，确定性动作（onnxruntime，与`climb_behavior_diagnostics.py`相同）。每个场地连续20回合，共64个场地×20回合×2个seed。环境参数与训练相同（target_mode 0，高度奖励k=0.2、C=0.2，只影响奖励，不影响动作） |
| 运行方式 | Editor播放模式（`ClimbZeroShot.PlayInEditor` + `scripts/run_zero_shot.py`），原因见§1.2 |
| 统计单位 | 结构。每个结构先算20回合的比率，再按难度汇总。另按LAYER3_DESIGN §11的近重复簇统计，簇是更保守的独立单位 |
| 数据 | [climb-zero-shot](data/climb-zero-shot/)：per_structure.csv、episodes.csv、summary.json；脚本`scripts/analyze_zero_shot.py` |

### 1.1 评估集的生成与冻结

- **规则**：每个难度从seed 10000开始依次生成，按以下规则跳过：
  - 与训练两级台阶几何相同；
  - 与已收录结构完全重复（箱体轴对齐包围盒按0.05m网格量化后的键相同）；
  - 动态落定失败。
- 每个难度收满30个为止，最多尝试2000个seed。**没有用任何控制器或策略的成败来筛选。**
- **结果**（【数据】）：

| 难度 | 收录 | 尝试seed | 跳过原因 | §11近重复簇数 |
|---|---|---|---|---|
| Easy | **3** | 2000 | 训练结构1000次，重复997次 | **1** |
| Standard | 30 | 34 | 重复3次，落定失败1次（粗可达） | 7 |
| Hard | 30 | 33 | 重复1次，落定失败2次（倒塌） | 12 |

- 【数据】Easy只收到3个，没有达到要求的30个。生成器的Easy只有两种模板：
  - 奇数seed：与训练两级台阶完全相同；
  - 偶数seed：单个Tall箱，只有0.95/1.00/1.05三种缩放。
  - 这在LAYER3_DESIGN §9第2项已有记录。
- 【数据】按§11的独立性定义（相同支撑图、所有箱体边界相差≤0.05m即归同簇），实际独立的形状只有1/7/12簇。30个Standard/Hard结构中，很多只是缩放±5%或偏移0.05m的变体。
- **不能用这个集合做正式评估**：§11要求每档至少50个独立结构。本轮是一次零样本探查，n如实报告；置信区间同时给出按结构和按簇两种。

### 1.2 为什么在Editor中运行，以及与Player是否一致

- 这个worktree无法构建独立Player：Windows应用程序控制阻止加载新解出的`Burst.Backend.dll`（HRESULT 0x800711C7）。绕过该安全控制的做法没有执行。
- 因此改为在batchmode Editor中进入播放模式，由Python通过Editor端口驱动。场景、Agent、观测、动作和observer与Player相同。
- 两处配套改动：
  - `ClimbEpisodeLog`原先在Editor中完全不写文件。现在只有显式传入`--climb-output=`时才写，测试和手动试玩仍不写。Player行为不变，本轮也没有重新构建Player。
  - `PlayInEditor`等待启动时的"Define symbols changed"重编译结束后才进入播放模式。第一次冒烟测试因为这个重编译而断线，日志被异常刷屏，已停止并删除。
- 【数据】对照场地的结果与Player评估一致：
  - s2027：20/20成功，Player为200/200；
  - s2026：15/20，Player为175/200。第一回合成功，3个回合有遗留关节的早抓迹象（见§3.3）。
- 【推断】Editor路径没有引入可见偏差。对照只有20回合，只能排除大的偏差。

## 2. 结果

### 2.1 按难度（每结构20回合；均值为结构平均）

| seed | 难度 | 结构数（簇数） | 一级 | 二级 | 成功 | 有成功的结构数（Wilson 95%） | 第一回合成功 |
|---|---|---|---|---|---|---|---|
| s2026 | 对照（训练两级台阶） | 1 | 85% | 75% | 75% | — | 1/1 |
| s2026 | Easy | 3（1） | 0 | 0 | 0 | 0/3 [0, 56%] | 0/3 |
| s2026 | Standard | 30（7） | 0 | 0 | 0 | 0/30 [0, 11%]；按簇0/7 [0, 35%] | 0/30 |
| s2026 | Hard | 30（12） | 0 | 0 | 0 | 0/30 [0, 11%]；按簇0/12 [0, 24%] | 0/30 |
| s2027 | 对照 | 1 | 100% | 100% | 100% | — | 1/1 |
| s2027 | Easy | 3（1） | 55% | 67% | **67%** | 2/3 [21%, 94%] | 2/3 |
| s2027 | Standard | 30（7） | 0 | 0 | 0 | 0/30 [0, 11%]；按簇0/7 [0, 35%] | 0/30 |
| s2027 | Hard | 30（12） | 0 | 0 | 0 | 0/30 [0, 11%]；按簇0/12 [0, 24%] | 0/30 |

- 【数据】Standard和Hard的60个结构，两个seed各1200回合：**一级、二级、成功全部为0**。结束原因几乎全是Timeout，s2026有1次OutOfBounds。
- 【数据】当所有结构都是0、或只有1个簇时，自助法区间退化为一个点，所以"有成功的结构数"一栏用Wilson区间。
- 结论上限：两个seed在这类结构上的成功结构比例，按结构计算<11%，按簇计算<35%（95%）。

### 2.2 按结构（Easy与对照；Standard/Hard全为0，见per_structure.csv）

| 结构 | 形状 | s2026 一级/二级/成功 | s2027 一级/二级/成功 |
|---|---|---|---|
| 训练两级台阶 | Wide 0.5m + Step 0.5m，第一级踏面深0.60m | 85% / 75% / 75% | 100% / 100% / 100% |
| easy-10002 | 单Tall箱，顶面0.95m | 0 / 0 / 0 | 65% / 100% / **100%** |
| easy-10016 | 单Tall箱，顶面1.00m | 0 / 0 / 0 | 100% / 100% / **100%** |
| easy-10000 | 单Tall箱，顶面1.05m | 0 / 0 / 0 | 0 / 0 / 0 |

- 【数据】一级/二级是按支撑高度阈值统计的指标（≥0.45m/≥0.95m，需要稳定支撑0.3s）。快速到达终点时可能跳过一级的判定，所以easy-10002会出现一级65%、成功100%。这与LAYER3_HEIGHT_SHAPING §3.3的现象相同。

### 2.3 行为差异（【数据】，episodes.csv）

| seed | 难度 | 有抓握的回合 | 最高躯干高度 p10 / p50 / p90 / 最大（m） |
|---|---|---|---|
| s2026 | Standard | 393/600 | 0.40 / 1.02 / 1.52 / 1.93 |
| s2026 | Hard | 586/600 | 0.98 / 1.00 / 1.02 / 1.39 |
| s2027 | Standard | 10/600 | 0.40 / 0.40 / 0.40 / 0.40 |
| s2027 | Hard | 40/600 | 0.40 / 0.40 / 0.40 / 0.85 |

- **s2027在新结构上几乎不动**：躯干一直停在出生高度0.40m，600回合中只有10/40回合出现抓握。
- **s2026会抓、会把躯干拉到约1m**，在Standard中偶尔到1.5–1.9m，但从未形成≥0.45m的稳定支撑。
- 【推断】两个seed在训练结构上都学会了，但在新结构上表现出两种不同的失效：
  - s2027的局部观测超出训练分布后，策略输出几乎不触发动作；
  - s2026保留了"抓住并上拉"的动作，但无法完成站上台面这一步。
  - 验证方法：比较新结构与训练结构起始几步的观测分布，以及动作输出的幅度。

### 2.4 成功与失败结构的形状差异

- Standard和Hard没有成功结构，所以无法做成功与失败的对比。唯一有对比的是Easy：s2027在顶面0.95/1.00m上成功，1.05m上失败。只有3个结构、1个簇，不能推广。
- **决定性的差异是第一级踏面深度**，这是生成器中一个固定的结构差异：

| 结构 | 第一级 | 第一级踏面深度 | 其上的竖直面 |
|---|---|---|---|
| 训练两级台阶 | 0.50m | **0.60m** | 0.50m |
| Standard/Hard全部60个 | 0.50m（Step） | **0.05–0.30m**（Standard 0.05–0.15，Hard 0.15–0.30） | **0.95–1.05m**（Tall） |

  - 【数据】这是从冻结JSON的几何键读出的；Standard/Hard的第二层Tall箱只比第一层后退0.05–0.30m（`BoxStackGenerator.Generate`）。
  - 【推断】训练中学到的路线是"在0.5m台阶上站稳 → 再上0.5m"。新结构上没有可以站稳的第一级踏面，需要从窄沿攀上约1m的竖直面。这是训练中从未出现过的技能，Easy单箱的结果也与此一致（s2027只在≤1.00m时成功）。
- 以s2026的平均最高躯干高度作为次要指标，在结构间做Spearman相关（【数据】，描述性，n=30，不做显著性检验）：
  - **Standard**：与最大层高差0.67、与悬挑数0.51、与间隙宽度−0.81、与暴露顶边数−0.58。
    - 带0.10m间隙侧塔的10个结构，以及4层结构，躯干都停在0.40m；
    - 最大层高差0.95–1.05m的结构，平均到1.11–1.23m。
  - **Hard**：与总高度−0.66、最大竖直面−0.64、层数−0.46。
  - 【推断】这些相关混杂了生成器的模板结构：Standard的层数、间隙和偏移都由seed的模运算联动决定，特征之间不独立。所以不能把单个特征当作原因。

### 2.5 结论

1. **端到端策略没有零样本泛化。** 【数据】在训练以外的箱子结构上，只有s2027在两个单Tall箱上成功；Standard/Hard的60个结构、两个seed共2400回合中，一级为0。
2. **这个结果主要反映生成器分布与训练结构的差距，而不只是"泛化能力弱"。** 【推断】生成器的Standard/Hard统一采用"窄踏面 + 约1m竖直面"，与训练两级台阶的关键几何不同。
3. **评估集本身不满足§11。** 【数据】独立簇只有1/7/12。要做正式评估，必须先扩展生成器。

## 3. 两个需要注意的问题

### 3.1 ResetBody遗留关节

- 见[LAYER3_RESETBODY_DIAGNOSTIC.md](LAYER3_RESETBODY_DIAGNOSTIC.md)。回合以握着结束时，下一回合开始时那只手会被拉回旧抓握点。
- 本评估每个场地连续运行20回合，后续回合可能受影响。【数据】s2026的早抓回合（开始后0.12s内抓住）：
  - 对照场地3个，Easy 28个，Standard 5个，Hard 52个；
  - s2027为0。
- 【数据】所有成功或失败的结论与只看第一回合（干净出生）时相同：Standard/Hard第一回合为0/60，Easy为s2026 0/3、s2027 2/3。
- 遗留关节已修复（[LAYER3_HEIGHT_SHAPING.md](LAYER3_HEIGHT_SHAPING.md) §6）。本节结果是修复前测得的；因为结论只依赖第一回合，没有重跑。

### 3.2 Editor运行路径

见§1.2。正式评估前，应在能构建Player的环境中（例如主工作目录，或把Burst.Backend.dll加入应用程序控制白名单后）用Player复核一次。

## 4. 下一步建议（待确认，未实施）

### 4.1 前置工作

1. **决定是否修复ResetBody遗留关节**。如果要在生成器分布上训练，以握着结束的回合会更多，非标准出生状态也会更多。建议先修复，作为独立提交。
2. **扩展生成器的几何多样性**，作为独立任务验收，不与训练同时改。
   - 按LAYER3_DESIGN §9第2项、§11的要求，让参数连续或细分取值：
     - 每级高度0.3–1.05m，踏面深度0.1–0.8m；
     - 台阶宽度、横向偏移、镜像、层数；
     - 是否有侧塔、间隙宽度。
   - 去掉seed模运算造成的特征联动，让每个参数独立抽样。
   - 验收指标：
     - 每档按§11聚类后≥50个独立簇；
     - 落定通过率；
     - 特征覆盖直方图；
     - 脚本控制器的可解率只作为信息参考，不用于筛选结构。
3. **评估集与训练集按簇划分**：同一簇只能进入一个集合。冻结manifest和sha256，记录生成seed。

### 4.2 课程设计（训练只改"结构分布"这一个变量，其余沿用climb_height_shaping.yaml）

| 阶段 | 结构 | 目的 | 晋级条件（在本阶段的训练分布验证结构上，确定性） |
|---|---|---|---|
| C0 | 训练两级台阶 + 单箱（顶面0.5–1.05m，连续） | 保留已学技能，覆盖单一竖直面高度 | 成功率≥80% |
| C1 | 两级，踏面深度从0.6m逐步减到0.1m，层高0.3–0.6m | 学会窄踏面和不同层高 | ≥70% |
| C2 | 两级，第二级为约1m竖直面；或三级 | 对应当前Standard的核心难点 | ≥60% |
| C3 | 三到五级，悬挑、侧塔、间隙 | 对应Hard | ≥40% |

- 混合采样：每个阶段保留20–30%的前一阶段结构，防止遗忘。
- 晋级只看验证结构，不看评估集。
- 示范出生：现有状态库只来自训练两级台阶，脚本控制器也只能解单箱和固定两级台阶。【推断】第一版保持示范出生只用于两级台阶，其余结构正常地面出生，不新建状态库。
- 高度奖励：C=0.2时，约1m就会封顶（k=0.2/m）。2–2.5m高的结构上，后半段没有shaping。【推断】第一版保持不变以遵守单变量原则；如果C3卡住，再把"按结构总高度缩放C"作为下一个单变量实验。

### 4.3 步数估计（【推断】）

- 单一两级台阶：s2027约3M步收敛，s2026到5M仍在上升。
- 按每阶段3–8M步估计，四个阶段合计**约20–30M步/seed**。
- 吞吐按本轮实测5M步约1950–2050s计算：20M约2.2小时，30M约3.4小时。两个seed串行约4.5–7小时。
- 建议先跑C0+C1（约8M步）作为可行性检查，再决定是否继续。每次实验只改一个变量，并使用新的run-id。

### 4.4 评估集规模

- **每个难度至少50个独立簇**（不是50个seed），各取一个代表结构。建议每结构20回合，并在修复遗留关节后使每个回合都是干净出生。
- 【数据】0/50时Wilson 95%上限约7%；在50%附近，区间半宽约±13–14个百分点。
- 如果要区分相差10个百分点的两个策略，需要约100个簇/档。
- 统计单位为簇；报告按簇的均值与区间、按簇的"有成功"比例，并保留训练两级台阶作为回归对照。

### 4.5 第3层完成标准（提案，待确认）

在冻结的评估集上（每档≥50个独立簇，与训练/课程结构不同簇），地面出生，确定性评估，至少2个seed，每个seed单独满足：

| 项目 | 标准 |
|---|---|
| Easy成功率（按簇均值） | ≥80%，且95%下限≥70% |
| Standard成功率 | ≥60%，且95%下限≥50% |
| Hard成功率 | ≥30%，且95%下限≥20% |
| 训练两级台阶回归 | ≥90% |
| Fall + OutOfBounds | 每档≤5% |
| 运行条件 | ResetBody遗留关节已修复或已证明无影响；用Player复核Editor路径 |

阈值是提案，可以根据扩展后生成器的实际难度调整。调整时应在看到正式评估结果之前确定（预注册）。
