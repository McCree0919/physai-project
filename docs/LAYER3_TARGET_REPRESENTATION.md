# Layer 3：手部目标表示对照实验（incremental vs absolute）

本实验对应诊断报告第4节第2项和第5.3节第5条：比较增量（`target_mode=0`，q←Project(q+0.08·a)）与绝对（`target_mode=1`，q=Project(0.85·a)）两种手部目标表示。主要的机制指标是抓握期间躯干受到的竖直力。

## 1. 设置

| 项目 | 值 |
|---|---|
| 组合 | 2种表示 × 3个seed（2026/2027/2028），每次5M步 |
| 配置 | `config/climb_target_incremental.yaml`、`config/climb_target_absolute.yaml`，两者只有`environment_parameters.target_mode`不同；与`climb_pilot.yaml`相比，改动的是max_steps、checkpoint和device |
| 训练 | CPU，4个实例，依次运行；`scripts/run_target_representation.py`（commit 78c3f39） |
| 训练耗时 | 每次1835–1993s，约2,500–2,700步/s |
| 评估 | 取最接近1M/2.5M/5M的checkpoint，确定性输出，每个checkpoint 200回合，worker-id 41，评估时使用与训练相同的target_mode |
| 时间 | 2026-11-09 20:03 – 23:29；6次训练和18次评估全部完成（`ALL_COMPLETE`），没有失败或非零退出码 |
| 数据 | [climb-target-representation](data/climb-target-representation/)：per_seed.csv、summary.json（均值/标准差/最小/最大）、每个checkpoint的metrics.json、episodes.csv、runtime.csv，以及runner.log |

指标口径与诊断报告第5节相同。合法接触：未抓握手的某个物理采样上，`GetGripCandidate`返回Allowed。躯干竖直受力：−F_y，正值向上，只统计抓握手的采样。

## 2. 主要结果：6次训练都没有产生攀爬

**18个checkpoint × 200回合，Level-1、Level-2和成功率全部为0。** 训练过程中（随机策略）的TensorBoard统计也一样：

| run | 训练期`RewardProgress` | 累计奖励 | 训练期最高躯干高度（单次统计最大值） | 结束原因 |
|---|---:|---:|---:|---|
| incremental s2026 | **始终为0** | −1.12（常数） | 0.75m | Timeout ≈100% |
| incremental s2027 | **始终为0** | −1.12 | 0.72m | Timeout 99.7%，OutOfBounds 0.3% |
| incremental s2028 | **始终为0** | −1.12 | 0.98m | Timeout 100% |
| absolute s2026 | **始终为0** | −1.12 | 0.41m | Timeout 100% |
| absolute s2027 | **始终为0** | −1.12 | 0.49m | Timeout 100% |
| absolute s2028 | **始终为0** | −1.12 | 0.44m | Timeout 100% |

在全部30M步里，没有一个回合拿到过进度奖励：没有在≥0.45m的支撑面上稳定站住0.3s，也没有支撑高度+0.2m的事件。回报中只有时间惩罚，每个回合都相同。**也就是说，PPO在这6次训练中没有收到任何区分好坏行为的奖励信号。** 下文各checkpoint之间的差异，应理解为策略在无信号条件下的漂移，而不是学到的行为。

> **口径更正（2026-11-10）**：Agent的Level-2指标曾在"到达终点、成功结束回合，但尚未满足第二级0.3s稳定支撑"时漏计（快照录制中发现，128条专家轨迹全部Success但level2=0）；已改为成功即记Level-2，只改指标，奖励不变。本报告（18个checkpoint×200回合，以及训练期全部回合）成功回合为0，不可能发生漏计，所引用的第二级登层率不受影响。详见[LAYER3_SNAPSHOT_DESIGN.md](LAYER3_SNAPSHOT_DESIGN.md) 8.7。

## 4. 抓握期竖直受力分布：absolute vs incremental（基线−219N）

**判断：方向问题没有因为换成absolute表示而消失，而且在本实验中absolute并不比incremental好。**

- 有数据支持：
  - absolute有抓握的4个checkpoint中，3个的回合**全部**向下受力（−48 / −155 / −185N），合并后按采样加权为−171N，与基线−219N同号、同量级。
  - 唯一向上的absolute checkpoint（s2026 5M，+8N），平均每回合只抓0.03s，对身体没有实际作用。
  - absolute抓握期的目标半径并不贴边（0.35–0.60m，≥0.84m的比例≤2.6%；s2026 5M例外，为71%），但力仍然向下。这直接证实了诊断报告第5.3节第4条：**半径不是因果变量，方向才是**。absolute消除了“偏置累积到边界”，却没有消除“目标指向握点上方/外侧”。
  - incremental的3个checkpoint出现了向上受力的回合（最高+46N，s2028 5M，98%的回合向上，平均抓握3.56s）。即便如此，最高躯干只到0.455m（P95），没有一个回合达到Level-1。
- 推断（未直接测量）：
  - 由于全部30M步都没有进度奖励，这些力的方向不是被奖励塑造出来的，而是每个checkpoint在无信号漂移中碰巧形成的确定性策略。因此不能把“incremental的部分checkpoint向上”归因于表示的优势。要验证，需要在有奖励信号的条件下重做对照（见第6节）。
  - 单个+46N的回合说明“向上”本身不足以撑起身体：体重约117.7N，按下压撑起方式抬升躯干需要持续超过体重的净向上力，并且要配合站上台面。这是基于受力量级的推断，没有在本实验中测量“向上力与抬升高度”的关系。

## 5. 其他观察

1. **absolute确实消除了目标贴边**（有数据支持）：全回合目标≥0.84m的比例从incremental的65–92%降到0.6–11%。这是表示改变后唯一一致且显著的差异，与设计预期一致（第13节）。
2. **absolute的随机探索更"安静"**（训练期数据支持）：训练中absolute的最高躯干单次统计最大值为0.41–0.49m，incremental为0.72–0.98m。
   - 推断：absolute下每个决策（0.1s）的随机动作独立抽取一个新目标，手在原地附近抖动。incremental下的随机动作积分成持续的位移，更容易把身体撑高或推离地面。这与诊断报告中"随机动作（incremental）最高能到1.0m"一致。可以用"随机策略分别在两种模式下跑N回合，比较最高躯干分布"来验证，本轮没有做。
   - 如果这一推断成立，在纯探索阶段absolute反而更难碰到Level-1，会让本来就为零的奖励信号更难出现。
3. **合法接触**（有数据支持）：incremental的合法接触率总体高于absolute（5M时1.99% vs 0.16%）。incremental 5M的3个seed都有≥99.5%的回合出现过合法接触，absolute只有39%。但"抓住"不是瓶颈的全部：incremental s2027 5M在100%的回合有合法接触，抓握却是0%，说明策略已不再在接触时发出抓握请求。
4. **seed间方差极大**：同一配置的checkpoint在0%与100%抓握之间跳动，确定性策略坍缩成"每回合都同一种行为"。在无奖励信号的条件下，这是预期现象（推断）。

## 6. 结论与建议

1. **本实验不能区分两种表示对"学会攀爬"的影响**：两者都在0奖励信号下训练，Level-1/Level-2都是0。这是实验的主要发现，比表示之间的差异更重要。
2. **方向问题不随表示而改变**：absolute抓握期的竖直受力仍以向下为主（合并−171N，基线−219N）。absolute只修正了半径贴边，这一点与"方向而不是半径"的诊断结论一致。
3. **瓶颈是探索：从地面出发，随机探索在5M步内一次也没有达到可奖励的状态。** 这直接支持正在实现的快照/演示状态初始化（LAYER3_SNAPSHOT_DESIGN.md）：S2/S3阶段的出生点让策略从已抓握、正在拉起、已在Level-1的状态开始，进度奖励才可能出现。
4. 建议（待确认）：
   - 默认表示保持incremental不变（本实验没有给出更换的依据）。
   - 快照实现提交后，在相同的2×3设置上加入快照出生点，重做一次对照；那时才能检验表示对学习的影响。
   - 每次只改一个变量：先只开启快照出生点（incremental），确认`RewardProgress`不再为0，再做表示对照。
