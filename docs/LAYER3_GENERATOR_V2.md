# Layer 3：箱子堆叠生成器v2、物理可行性约束与按簇划分

【数据】为有测量或源码支持的结论；【推断】为设计判断，并注明如何验证。用户决定（2026-11-10）：扩展生成器，每个难度至少50个独立簇，按簇划分训练与评估；另加由身体参数推导的最小踏面深度硬约束。

## 1. 为什么需要v2

【数据】v1生成器（[LAYER3_ZERO_SHOT.md](LAYER3_ZERO_SHOT.md) §1.1）存在两个问题：
- 层数、偏移和侧塔都由seed的模运算联动决定。按§11聚类后只有1/7/12个独立簇。
- 所有Standard/Hard结构都是"0.05–0.30m窄踏面 + 约1m竖直面"。躯干站不上这样的踏面（见§2），所以这些结构要求的是另一种技能，与"泛化"无关。

## 2. 物理可行性约束的推导

### 2.1 身体参数（【数据】，源码）

| 量 | 值 | 出处 |
|---|---|---|
| 躯干盒 x×y×z | 0.60 × 0.80 × 0.35 m，10kg | `ClimberArenaFactory.Create` |
| 躯干旋转 | 锁定X、Z，只有yaw自由 | `ClimberBody.LockRotationX/Z` |
| 肩部 | 躯干中心(±0.30, +0.28, 0) | `ClimberBody.shoulders` |
| 手 | 球，直径0.20m，1kg | `ClimberArenaFactory.Create` |
| 手目标 | 距肩0.15–0.85m（命令钳制），关节极限0.90m | `ClimberBody.SetHandTarget`、`ArmLength` |
| 稳定支撑 | 从躯干中心和(±0.30, ±0.175)共5条向下射线都打到同一个顶面（高度差≤0.02m，法线·上≥0.95，躯干底面距顶面−0.005至+0.085m），速度<0.25m/s，持续0.3s | `ClimberAgent.TrySupport` |
| 抓握 | 手心距顶面点≤0.111m，且不低于该点 | `ClimberBody.CheckCandidate` |

测试`GeneratorV2Tests.ClimberGeometryMatchesTheLiveBody`断言下列推导所用的常量与运行中的身体一致。

### 2.2 能稳定站立的最小踏面深度

- **决定性的约束是任务对"站立"的定义，不是倾覆。**
  - 躯干X、Z旋转被锁定，不会向前或向后倾倒。只要底面与踏面有接触，刚体就能停住，所以质心落在支撑面内（踏面>0.175m）这个通常的倾覆条件不起作用。
  - 但第3层的登层、进展奖励和成功都基于`TrySupport`：5条射线中，4条位于躯干足迹的四个角(±0.30, ±0.175)，必须都打在同一个顶面上。也就是说，**整个0.60×0.35m的足迹都要落在踏面上**。
- **严格的几何下限**：yaw为0且位置完全对准时，深度0.35m，宽度0.60m。
- **设计约束**：加上容差，yaw ±5°、位置 ±0.025m。
  - 深度：d_min = 0.35·cos5° + 0.60·sin5° + 2×0.025 = 0.3487 + 0.0523 + 0.05 = **0.451m**
  - 宽度：w_min = 0.60·cos5° + 0.35·sin5° + 2×0.025 = **0.678m**
  - 净空：踏面上方0.80 + 0.05 = **0.85m**内不能有其他箱体
- 生成器所有尺寸都在0.05m网格上，因此**实际生成的最小站立踏面为0.50m**。训练两级台阶的踏面为0.60m，满足约束。
- 【推断】±5°和±2.5cm是设计选择，不是测量值。验证方法：用脚本控制器在踏面0.45–0.60m的两级结构上统计站稳成功率（§5的审计中，v2评估集的踏面都≥0.50m）。

### 2.3 够得着的边缘与"需要站立的层级"

- 站立时，肩部高出所站表面0.40 + 0.28 = **0.68m**。手心必须到达边缘点，且距肩部不超过0.85m。
- **判据**：边缘点到某个站立位置的左肩或右肩的距离≤0.85m。
  - 边缘点在前方时，水平距离至少是躯干半深加手半径0.175 + 0.10 = 0.275m。
  - 由此，竖直方向最多可以够到所站表面以上 0.68 + √(0.85² − 0.275²) = **1.484m**（`ClimberGeometry.Reach`）。
- **站立位置**：
  - 在箱顶上：足迹（带容差）完全落在顶面内、上方净空内没有其他箱体的0.05m网格位置；
  - 在地面上：身体不能行走，只取出生位置（躯干中心(0, 0.4, −0.4)）。
    - 第一版曾允许出生点0.5m半径内的位置。审计时发现，在这个假设下，从地面"恰好够得着"（0.848m，限值0.85m）1.0m层的边缘，于是路线跳过了第一层。
    - 【数据】实际上，在双手抓住之前，躯干一直停在出生点z=−0.40，脚本控制器在这些结构上卡在第一次抓握。
    - 因此改为只取出生位置。生成器窄沿的可跳过判定同步改用出生位置，评估集和训练池按新规则重新冻结；此前没有任何v2评估。
- **可行性检查**（`BoxStackFeasibility.Check`，只看几何，不涉及控制器和策略）：
  - 从地面开始做广度优先搜索：若某个顶面至少有一个站立位置，且从当前顶面的某个站立位置够得着它的边缘，就可以到达它。
  - 若能到达最高箱（终点所在的箱），同时v1的粗可达检查也通过，则判定为可行。
  - **需要站立的层级**：从图中去掉它之后终点不可达的顶面。例如训练两级台阶的下层：从地面够不到1.0m层的边缘，因为它在出生点前方1.0m。
- **生成器的硬约束**：
  - 每个需要站立的层级，踏面≥d_min，向上取整到0.50m；
  - Hard可以有一个更窄的"窄沿"（0.10–0.40m），但只在可以跳过时才保留：从窄沿下方站立位置的肩部，必须够得着窄沿上方那一层的边缘，否则重抽。所以窄沿永远不是需要站立的层级。
  - 测试`GeneratorV2IsValidAndFeasibleByConstruction`：三档各200个seed全部通过可行性检查，所有需要站立的层级可站立深度都≥0.451m。
- 【推断】这是运动学上限，不保证能够完成攀爬：没有考虑力的预算、动态过程和抓握时序。它只用作审计和成功率的分母，不用来筛选结构。

## 3. 生成器v2（`BoxStackGeneratorV2`，generator version 2）

- **仍只用Step/Tall/Wide预设**（尺寸×0.95/1.00/1.05，质量固定），与用户搭建攀爬架时可用的物体库一致。
  - 代价：单层高度只有约0.5m（Step、Wide）和约1.0m（Tall）两档。
  - 变化来自摆放参数，不另加任意尺寸的箱体。
- **每一层的箱体放在上一层箱顶上，比上一层后退"该层踏面深度"**。各参数独立抽样，没有模运算联动：

| 参数 | Easy | Standard | Hard |
|---|---|---|---|
| 层数（抽样） | 1–2 | 2–3 | 3–5 |
| 每层预设 | 第1层任意；以上只用Step/Wide（不在踏面上方放1m竖直面） | 任意 | 任意 |
| 站立踏面 | 0.50m至min(0.80m, 支撑上限) | 同左 | 同左；另有50%概率出现一个可跳过的窄沿0.10–0.40m |
| 上层横向偏移 | ±0.20m | ±0.20m | ±0.30m（可形成侧向悬挑） |
| 侧塔（Tall/Step） | 无 | 30%，间隙0.10–0.40m | 60%，间隙0.10–0.40m |

- **支撑规则**：上层箱的中心在下层顶面内至少0.10m，横向和纵向都是。放不下时重抽，最多40次；仍失败，就在这一层截断结构。
- 动态落定仍由`BoxStackSettlement`独立检查（倒塌、漂移、穿透）。这是物理筛选，与任何控制器或策略无关。
- `StructureJson.Validate`接受`boxStack`的版本1和2。v1生成器与已冻结的v1集合不变。

## 4. 冻结集合与按簇划分（`ClimbGeneratorV2Sets.Freeze`，`structures/box-stacks-v2/`）

### 4.1 规则

- **独立性**：同§11，并加入镜像等价。
  - 两个结构"相连"的条件：箱体轴对齐包围盒按0.05m网格量化、排序后，支撑图相同（含着地位），并且每个包围盒坐标相差≤1格（原样或x镜像后比较）。
- **评估集**（`eval/`，seed从20000起，按顺序）。满足以下全部条件才保留，每档收满60个：
  - 落定通过；
  - 不是单箱（单箱留给训练）；
  - 不与训练两级台阶相连；
  - 不与已保留的任何评估结构相连。
  - 所以每个评估结构自成一簇。
- **单箱保留给训练**：单箱只有约4个独立簇（Step、Tall、Wide两个朝向），而课程C0要在单箱上训练。按簇划分时它们只能进入一边，所以放在训练侧。这个规则在任何v2评估之前确定。
- **训练池**（`train/`，seed从100000起）。满足以下条件才保留，每档最多300个，最多尝试5000个seed：
  - 落定通过；
  - 不是完全重复；
  - 不与任何评估结构相连。
- **可行性**：每个结构都记录在manifest里，只供审计，不参与保留或丢弃。

- 表中是按出生位置规则重新冻结后的结果（§2.3）。"有需要站立层级"几乎是全部，因为从出生位置只够得着第一级的边缘；只有12个单箱不需要中间站立。

- 构造层数是最高箱的支撑堆叠层数（`BoxStackFeatures.constructionLevels`）。Standard中有1层的结构，是因为上层放不下而在第1层截断，这类结构带侧塔。

- **独立复核**：用`scripts/analyze_zero_shot.py`中的Python聚类（独立实现，不含镜像，因此更宽松）对评估集∪训练池整体聚类。
  - 混合簇为0；
  - 评估集每档60个结构对应60个簇。
  - 每个训练结构到最近评估结构的包围盒差≥2格（0.10m）。所以即使按传递闭包聚类，也不会把训练和评估连到同一个簇。
- **【数据】Hard被物理筛选得很重**：约90%的Hard候选在落定时倒塌（评估514/575，训练2718/3023），4–5层的堆叠大多倒塌。保留下来的Hard集中在3层，评估集中构造层数4的只有2个。
  - 【推断】这是箱体堆叠的真实物理限制，不是生成器的缺陷。若要更高的Hard，需要更稳的堆法，例如Tall作底座、更宽的下层，这可以作为下一个单变量改动。
- 【数据】可行性检查在v2三档评估集上全部通过，这与生成器的硬约束一致。审计（§5）另外报告脚本控制器能否完成。
