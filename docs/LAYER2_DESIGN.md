# 第 2 层设计：结构、动态抓点与玩家搭建

状态：**用户已确认范围（2026-11-09）**。实施顺序为静态结构 JSON 保存/加载与程序化生成器 → 运行时搭建工具 → 动态箱子。本轮只实现第一步。第 1 层身体、抓握逻辑、手动控制、既有测试和物理设置保持原样。

## 1. 范围与不变量

第 2 层让程序化结构和玩家结构进入同一条数据、物理构建和验证路径。保持身体 12 kg、臂长 0.90 m、支撑/自由手 450/40 N、现有 PD 与力偶补偿不变；不能为了某结构可解临时增加身体能力。所有控制器仍只走身体公开接口。第 3 层的策略、观察、奖励与训练课程不在本轮实现。

先交付静态结构保存/加载、生成器与落定验证，再做运行时搭建工具，最后动态箱子。运动学抓点、一般动态闭环、旋转解锁与肩部扭矩预算从计划移除；保留现有旋转约束与非径向内力反力偶补偿。完整事件与 GetLoadState 仅按动态箱子实际需要评审。

## 2. 共用结构 JSON v1

### 2.1 坐标与数据合同

UTF-8 JSON，长度 m、质量 kg、时间 s、角速度 rad/s、力 N。所有位置/旋转相对结构根节点；根节点只允许平移与旋转，scale=(1,1,1)。尺寸写入形状参数，不用层级非均匀缩放。四元数顺序 [x,y,z,w]，必须有限且归一化。稳定 ID 在保存、验证快照和运行日志间保持一致。

  "id": "example-static-wall",
  "units": {"length": "m", "mass": "kg", "time": "s"},
  "bodyProfile": "layer1-validated",
  "generator": {"name": "rungWall", "version": 1, "seed": 42,
    "parameters": {"heightGap": 0.25, "lateralGap": 0.40}},
  "materials": [{"id": "lowFriction", "staticFriction": 0.15,

    "bounciness": 0.0, "bounceCombine": "Average"}],
  "objects": [
    {"id": "ground", "type": "box", "size": [4.0,0.2,4.0],

      "motion": "static", "massKg": null, "materialId": "lowFriction",
      "graspable": false},
    {"id": "rung0", "type": "box", "size": [0.5,0.1,0.25],
      "pose": {"position": [-0.2,0.95,-0.075], "rotation": [0,0,0,1]},

    "rightHand": {"position": [0.3,0.95,-0.05], "rotation": [0,0,0,1]}

该例仅说明格式，故意未列齐中间横档，不能当作已通过可解性验证的完整关卡。程序化生成器与玩家编辑器都输出 objects/start/goal；generator 对手工结构可为 null，不用 seed 重建来替代保存实际物体。

对象类型首批支持 box；后续 sphere/capsule/convexMesh 扩展需版本和形状专用校验。旧横档静态物体无Rigidbody且massKg=null；新堆叠箱子即使运行时冻结，也记录预设质量供动态落定，见第10节。运行时dynamic/kinematic仍明确拒绝，不以mass=0表示静态。材质必须引用存在的ID，每个Collider显式分配，统一静/动摩擦0.15、Average、弹性0。

Box 的顶面/顶边由尺寸和运行时当前旋转，按相对重力的法线判定自动计算；倾倒后重新求顶面，不保存过时的世界顶面标签。边缘法线阈值、接触与上方侧判定沿用已验收身体语义。非基本形状以后可添加物体局部标记，加载时转换并验证；不把人工标记扩散到 Box。

导入校验：版本已知、ID 唯一、所有数值有限、尺寸/质量合法、材质引用存在、起点不穿透且手臂初始长度合法、目标有正体积、零缩放/未知类型拒绝。物体上限32，最薄碰撞体0.10 m；玩家首版采用2–3种固定尺寸箱子、每种质量固定，不开放自由缩放/质量输入。报错包含 JSON 路径与对象 ID。未识别的主版本不得静默解析。不要从 JSON 加载任意脚本、资产路径或可执行代码。

### 2.2 验证记录与快照

validation 记录 schema/generator/body/controller 版本、输入内容 hash、Unity 与 solver 配置摘要、seed、落定指标、可解性试验条件/结果和原因。它是派生缓存；结构或身体版本改变即失效。保留玩家原始摆放姿态，另存 settledSnapshot（物体 ID→落定姿态和初速度），训练/回放选择明确的快照并清零速度。不得自动用落定结果覆盖原稿。

## 3. 程序化生成与难度

目标决定补充：程序化结构应以箱子堆叠为主，与运行时玩家搭建结构同属一类。难度由悬挑、缺少可抓顶面的竖直段、间隙、总体高度等形状特征定义，不以横档高差/横向间距作为目标课程。下节横档参数带记录的是当前诊断实现，不代表该目标已经完成；是否重做生成器待本轮只读核查后决定。

### 3.1 使用本轮证据

[扫描报告](LAYER2_SOLVABILITY.md)覆盖 h=0.15–0.60、s=0.20–0.80、步长 0.05，共 1040 次尝试。h≥0.35 的所有已测横距均 8/8；h=0.20–0.25 时 s≤0.30 全失败，较宽横距反而成功。因此难度不能只用“越小越容易”的单标量映射。

生成器不得以脚本成功率或试爬结果过滤结构，包括禁止离线“脚本成功格白名单”。它只检查输入合法性、物理稳定性与粗略几何可达性。脚本控制器仅用于简单难度冒烟测试，不能参与生成、重采样、保存或加载的准入判断，以免训练分布被限制在脚本能力内、破坏泛化研究。扫描只提供诊断证据。当前扫描每关四横档，平台高度随h变化，未隔离路程长度与单步难度。

扩展扫描0.60–1.00 m的117格/936次全部成功，未找到低于50%的边界。当前预设几何参数带：Easy h=0.20–0.30、Standard h=0.35–0.60、Extended h=0.65–1.00；三档s均0.20–0.80，默认采样步长0.05 m。GenerateAt接受这些总数值范围内的连续值，不要求落在扫描网格，也不检查脚本成功标签。Easy seed=0保留原基准，只供简单冒烟。

难度参数显式分开：高差、横距、横档宽/厚/深、路线长度、绕行障碍、初始位姿扰动、可动物体比例/质量/支撑面。初期锁定后四类，只对一种参数做实验。保持最薄实体0.10 m，只进行粗略几何检查，不检查某条脚本的撤离/抬高/插入轨迹。四横档生成器以相邻顶面最短距离不大于两臂总长1.80 m作为宽松必要条件，并检查结构重叠、起点与目标中心净空；这不是完整可解性证明。不得要求脚本路径无碰撞才能生成。

生成准入仅分输入不合法、物理/粗几何校验拒绝、通过。脚本成功/失败是独立诊断标签，不改变准入、采样权重或难度分配；不以脚本失败触发重采样，不改进脚本以追求全绿。训练前的简单冒烟仅验证基础链路，不筛选训练样本。

### 3.2 落定模拟（建议验收阈值，尚未实测）

保存前必须在隔离 PhysicsScene 的验证副本中执行落定模拟，不放角色，使用与训练相同固定步长/重力/材料；不稳定结构拒绝保存。在静态首批中，可抓取横档被视为固定世界支点，稳定性验证不把它偷偷变成自由动态物体；静态结构仍执行模拟和重叠/净空检查，并明确报告静态物体数与动态物体数。后续动态箱子最后连续 1 s 要求 |v|<0.02 m/s、|ω|<0.05 rad/s，至少模拟3 s、最长10 s；不能以 IsSleeping 单独证明受载稳定。

初始到落定净位移 >0.05 m 或倾角改变 >5° 时记录“发生重排”，决定是否接受落定后的另一个结构，而非装作原始搭建已稳定。跌出结构边界、持续滚动/摆动、严重穿透、NaN、关节异常和达到时限均失败。阈值需用稳定堆叠与故意不稳定反例标定，不能视作现有测试已通过。

空载落定后只检查起点和目标净空、抓点法线/高度及粗略几何可达性，不运行脚本筛选。动态结构另做单手约 118 N 静载与动作载荷探针测试：空载不倒不代表角色悬挂不倒。保存峰值速度、位移、倾角和断裂事件。禁止用偷偷改成 kinematic、世界固定或增大摩擦修复不稳定结构。

## 4. 动态抓点设计

### 4.1 连接与表面变化

当前身体会拒绝动态抓点，本轮保持该逻辑。未来获准后，沿用接触/速度/可抓层/同场地/几何顶面准入与 false→true 重新武装；查询 Collider.attachedRigidbody。真正静态物体 connectedBody=null；动态箱子连接其真实 Rigidbody，锚点分别由同一世界接触点变换到手和箱子的局部坐标。不得把动态物体抓握做成世界固定，不在抓住时瞬移或冻结箱子。

Box 转动后新抓握候选按当前姿态重新识别顶部；已成立的关节保持原局部锚点，不把手吸移到新的顶面。现有握点随物体运动，倾倒本身并不自动生成新抓握。是否因表面倾斜强制松手是待定规则，初期建议只影响新准入，已抓握靠断裂/主动释放决定。

### 4.2 承载、倾倒和断裂

身体重约 12×9.81=117.72 N；支撑箱自重与角色抓握载荷同时进入接触求解。静态悬挂并不意味着手臂一直主动输出 117.72 N，肩部被动约束可以承载，峰值负载需分开记录。

箱子是否倾倒取决于支撑多边形与外力矩。简化例：质量 10 kg、底宽 0.40 m，居中静止时绕底边恢复力矩约 10×9.81×0.20=19.62 N·m；若约118 N 的水平载荷施于高0.40 m处，倾覆力矩约47.2 N·m，可能先倾倒而未触发握点断裂。这个估算不能替代多接触的模拟，且“箱子至少10 kg”不等于可承载角色。抓住悬空箱子双方一起落下是合法物理结果。

保留抓握 breakForce=900 N / breakTorque=90 N·m；肩部连接仍不可断裂，仅记录峰值。不能用主动450 N解释所有关节冲击上限。关节断裂后清理逻辑占用，冷却0.30 s，必须先 false 再 true；主动松手冷却0.20 s。箱子与手质量比、碰撞模式、solver 调整仅限受审阅配置，禁止改全局物理参数。

诊断事件可包括 GripBroken、CandidateRejected、SupportLost、ObjectTipped、ObjectOutOfBounds；默认倾倒只记录诊断事件和评估指标。角色掉落、抓握断裂后无法恢复、物体越界或超时判失败；瞬时断裂本身不立即判失败。仅“保持结构不倒”专项任务将倾倒设为失败。恢复窗口和越界范围在动态任务实现时明确配置，本轮不凭空添加运行时判定。动态箱子还需验证释放/断裂重入、重置无残留连接、跨场地拒绝与运行中销毁物体。一般动态闭环从计划移除。

### 4.3 接口与守恒验收

未来身体继续是唯一施力与建关节主体，控制器不获可写 Rigidbody 引用。负载状态须区分主动命令与约束反力、采样时刻和坐标系。保留现有冻结旋转与非径向内力反力偶补偿；运动学抓点、一般动态闭环、旋转解锁、扭矩预算不进入第2层计划。

## 5. 玩家搭建工具

已确认采用运行时 UI，与试玩互斥：编辑时暂停角色与模拟，使用网格吸附，首版仅90°旋转。提供2–3种固定尺寸箱子，每种质量固定，物体上限32；不开放自由尺寸/质量编辑。网格建议0.05 m，具体箱子规格留到搭建工具任务，不阻塞本轮静态基础设施。所有 Collider 显式材质，Box 顶面自动计算。

界面支持多选、复制、删除、撤销/重做、对象ID和层级列表、起点与目标区域编辑。对象重叠、越界、起点穿透和不合法参数即时提示；试玩前执行静态校验与落定验证。试玩通过统一结构加载和身体 ResetBody 开始；手动与脚本均使用同一身体接口。退出试玩恢复编辑原稿，不把被推倒后的状态静默写回。

保存流程：编辑→数据/几何校验→必需的落定模拟→稳定才允许保存。不稳定结构拒绝保存，不允许以未验证草稿绕过门槛。保存到 `structures/<id>.json`，先写同目录临时文件并验证可重新解析，再原子替换；保留原稿，验证记录绑定输入hash，结构变化后失效。加载未知主版本或引用缺失给出明确错误，不丢物体后继续。玩家结构和程序生成结构都经过同一校验器。

## 6. 已确认决定与实施顺序

1. 静态结构JSON保存/加载与程序化生成器，含落定验证和基于扩展扫描的难度参数（本轮）。
2. 运行时搭建工具：网格吸附、90°旋转、2–3种固定箱子、每种质量固定、上限32物体、稳定才保存。
3. 动态箱子首轮质量10–30 kg；每种固定尺寸预设质量固定且在此范围内，不开放任意质量输入。默认倾倒仅诊断；掉落、断裂后无法恢复、物体越界或超时失败；保结构专项才因倾倒失败。
4. 运动学抓点、一般动态闭环、旋转解锁、扭矩预算从计划移除。
5. 不改进脚本以追求全绿。扫描停滞属于诊断终止，不等同正式任务失败判定。
6. PPO短时试跑为第3层第一步，本轮不训练。

以上替代准备总结中的旧待决项。本轮先将扫描扩展至高差0.60–1.00 m，仅将扫描作为诊断，不以脚本成功网格限制生成分布，不实现搭建UI或动态箱子。

API 依据：动态连接与 null 世界固定语义见 [Unity 6000.3 Joint.connectedBody](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/joint/connectedbody)；关节断裂属性见 [Fixed Joint 参考](https://docs.unity.com/en-us/engine/6000.3/manual/physics-section/physics-overview/joints-section/class-fixed-joint)。数值阈值和流程是本项目设计建议，不是 Unity 文档保证。

## 7. 本轮静态实现合同

`Assets/Scripts/Structures/` 提供 DTO/严格JSON解析、静态加载器、参数生成器、落定验证器和原参数脚本的调度适配器。首批只支持motion=static的Box，massKg必须显式null；dynamic/kinematic明确拒绝，不静默世界固定。玩家固定箱子预设在搭建UI任务落地，本轮不添加选择界面。

JSON中的position/size是三元素数组，rotation是归一化[x,y,z,w]。单位m/kg/s；未知字段、版本、重复属性/ID、非法值、材质缺失及超过32物体均拒绝。起点三刚体使用同一旋转，这是现有公开ResetBody接口的限制，不走额外Transform修改路径。目标沿用躯干中心0.30 s、速度<0.50 m/s合同。Box顶面判断复用已验收身体几何。

静态物体是明确的固定支点；保存前在隔离PhysicsScene执行至少3秒模拟，检查无重叠、出生点及目标中心的躯干净空，并确认固定物体未移动。验证报告注明staticObjects和dynamicObjects=0，不能证明自由堆叠箱子稳定。当前出现动态物体会直接拒绝，动态落定阈值留待动态箱子任务。Editor验证使用独立preview scene，运行时使用LocalPhysicsMode.Physics3D；禁止推进默认物理场景。相关API见[Unity PhysicsScene.Simulate](https://docs.unity.com/en-us/engine/6000.5/script-reference/unityengine/physicsscene/simulate)与[EditorSceneManager.NewPreviewScene](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/scenemanagement/editorscenemanager/newpreviewscene)。

保存必需重新验证，旧validation不作为授权；成功后存入输入SHA-256、Unity版本、固定步长、模拟步数与结果。临时文件在目标同目录，校验后原子替换；拒绝时不覆盖原文件。加载也重新验证，防伪造/过期验证标记。结构验证不等于脚本可解：只有canonical四横档可选自动脚本，任意玩家结构不伪装成可用原硬编码路线。

脚本仅用于Easy基准的冒烟，使用未改的ClimberScriptController；旧PrepClimbController及适配器保留为诊断工具，不作为生成或保存准入，不对Standard/Extended要求脚本成功。控制器只提交身体公开命令。具体用法与验收见[LAYER2_STATIC_ACCEPTANCE.md](LAYER2_STATIC_ACCEPTANCE.md)。

## 8. 补充决定对应的实现调整

已删除生成器的脚本成功格白名单，保留几何参数范围，加入宽松两臂跨度检查与静态验证；允许既有扫描中脚本0%成功的(0.25,0.20)、(0.20,0.20)等组合，也允许非网格参数。默认生成与加载均不创建控制器。JSON物体上限同步改为32，测试覆盖32接受/33拒绝。动态质量10–30 kg与细化失败规则目前为设计合同：本轮仍不实现动态箱子、搭建UI或任务失败管理器。

物理检查补充：h=0.15 m时末横档与厚0.20 m的顶部平台发生重叠，因此该参数会因几何穿插被拒绝；Easy预设从0.20 m起采样。此拒绝不参考脚本结果；回归测试单独验证其overlap原因。扫描原始数据保持不变。

## 9. 核查阶段确认的设计决定

1. 生成器不得以脚本可解性过滤结构，只检查输入合法性、物理稳定性和粗略几何可达性；脚本仅用于简单难度冒烟。此前已写入第3节，此处再次确认：不得使用成功格白名单、脚本失败重采样或脚本成功率调整训练样本权重。
2. 程序化结构以箱子堆叠为主，和玩家搭建结构共享同类构件、结构JSON及物理/几何验证流程；难度来自悬挑、缺少顶面的竖直段、间隙、总体高度等形状特征，而非横档间距。当前StaticWallGenerator仅为横档墙诊断实现，未实现该目标；本轮不改生成器，等核查汇报后再决定重做范围。
3. 默认身体参数保持不变。更弱的力量和更短的臂长仅作为评估时的“换身体”测试条件，用于研究迁移与泛化，不以削弱默认身体制造训练难度。具体评估参数、身体初始化/关节配置和指标在评估任务中另定，本轮不修改身体或新增测试条件。

## 10. 箱子堆叠生成器（本轮实现设计）

保留StaticWallGenerator及全部横档回归数据，新增BoxStackGenerator，和玩家搭建工具共用Box预设：Step=(1.20,0.50,1.20)m/15kg，Tall=(1.20,1.00,1.20)m/25kg，Wide=(1.80,0.50,1.20)m/25kg。运行时UI只选固定尺寸，程序生成允许统一缩放0.95–1.05，尺寸吸附0.05m网格；质量按预设固定，不改变默认身体。地面属于固定基础，不计入可动物箱预设。

构造在0.05m网格上组合台阶、塔、悬挑与间隙，每结构最多32物体。最高层顶面上设置躯干中心目标区域，尺寸(0.60,0.40,0.60)m，中心比顶面高0.60m；要求中心进入连续0.30s且速度<0.50m/s。目标必须有实际最高箱顶支撑，净空不足则物理/几何拒绝，不向脚本询问。

特征记录实际几何：最高箱的支撑堆叠层数constructionLevels、全场不同顶面高度数levels、粗图到目标最少跃迁数coarseMinimumTransitions、相邻层最大竖直差、单箱最大竖直面高度、暴露顶边高度序列最大间隔、悬挑数量/最大长度、间隙、暴露顶边数、总高度。前三者明确区分，不将几何层数当成策略必须执行的次数；粗图次数只是几何下界。Easy为1–2支撑层、无悬挑/间隙，单箱最高约1.05m；Standard为2–3支撑层、约1m高面，组合轻悬挑/可选间隙；Hard为3–4支撑层、更多悬挑及0.20–0.40m间隙。缩放、上层尺寸变化会影响实际悬挑长度，实测分布据实报告，不按脚本筛选。

抓握新增上方净空：从候选表面接触点沿训练场up方向上移0.005m开始，检查半径0.10m、高0.22m的手部进入柱体；排除当前承载Collider与自身身体，只考虑同场地实体。任何其他物体侵入则拒绝为TopOccluded。它检查局部点而不是整张顶面，被覆盖区域拒绝、暴露边缘仍可抓；横档间高差足够时行为不变。新增窄接缝、局部覆盖、完全覆盖的正反例，既有横档测试继续回归。

落定在隔离PhysicsScene执行：地面固定，所有箱子先为真实动态Rigidbody，显式0.15/Average/零弹性材质、预设质量。至少3s、最多10s；最后连续1s各箱速度<0.02m/s、角速度<0.05rad/s，窗口漂移<0.01m且角漂移<1°。相对输入总位移>0.05m或转角>5°、越界、穿透>0.005m均拒绝，避免把倒塌后的另一个结构当成功。睡眠状态单独记录，不单凭睡眠判通过。通过后保存落定位姿并移除临时刚体，运行时加载冻结为static。JSON追加可选presetId、settleAsDynamic、movable、massKg与生成特征；旧静态横档JSON无新字段仍可加载。本轮movable=false，未来动态箱子可用movable=true扩展，但目前不启用动态抓握。

粗可达检查基于暴露顶边图，从地面/起点到最高层存在候选连接；相邻顶边竖直差≤1.50m，同时要求宽松两臂跨度和顶边净空，不做脚本轨迹搜索。只以物理稳定性和粗几何拒绝结构；每档20个固定种子候选，不用补抽掩盖拒绝率。

新增独立BoxClimbSmokeController，只通过身体公开接口完成固定单箱和两级台阶：先双手抓前沿、撑起、向箱顶内移动，若第二级需要则在第一级落稳后释放并重新武装，再够第二级。两固定关卡各16场地。两级失败先输出阶段、躯干/双手位置速度、目标和抓握拒绝原因并汇报，不修改身体参数；不以这两个冒烟筛选生成分布。

实现细节：movable在新保存JSON中显式记录为false，settleAsDynamic=true说明加载前须真实动态落定，presetId与质量/缩放尺寸必须匹配。旧JSON缺省movable=false、settleAsDynamic=false，仍可读取。箱子关卡手部出生z=-0.15m，避免旧横档出生点穿入实心箱壁；不修改身体尺寸、质量、力或关节参数。新箱子落定允许接触求解的≤5mm穿透，旧横档静态验证仍用2mm；动态通过后以落定后几何做粗可达检查，再冻结。可抓顶边特征用每条顶边中点与0.20×0.22×0.20m保守净空盒抽样，运行时抓握则对实际接触点使用半径0.10m的胶囊查询；特征计数不是连续顶边可用长度的精确测量。
