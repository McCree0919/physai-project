# 第 2 层设计：结构、动态抓点与玩家搭建

状态：**设计提案，等待确认**。本轮仅实现隔离的静态扫描/性能工具；本文件中的 JSON 加载器、稳定性验证器、动态抓握和搭建 UI 均未实现。第 1 层身体、抓握逻辑、手动控制、既有测试和物理设置保持原样。

## 1. 范围与不变量

第 2 层让程序化结构和玩家结构进入同一条数据、物理构建和验证路径。保持身体 12 kg、臂长 0.90 m、支撑/自由手 450/40 N、现有 PD 与力偶补偿不变；不能为了某结构可解临时增加身体能力。所有控制器仍只走身体公开接口。第 3 层的策略、观察、奖励与训练课程不在本轮实现。

建议先交付静态结构格式/编辑/验证，再独立授权动态抓点。运动学抓点、一般双手动态闭环、肩部扭矩预算、解锁旋转的角动量试验、完整事件与 GetLoadState 都需要专门的实现和验收，不能用本轮静态扫描代替。

## 2. 共用结构 JSON v1

### 2.1 坐标与数据合同

UTF-8 JSON，长度 m、质量 kg、时间 s、角速度 rad/s、力 N。所有位置/旋转相对结构根节点；根节点只允许平移与旋转，scale=(1,1,1)。尺寸写入形状参数，不用层级非均匀缩放。四元数顺序 [x,y,z,w]，必须有限且归一化。稳定 ID 在保存、验证快照和运行日志间保持一致。

```json
{
  "schemaVersion": 1,
  "id": "example-static-wall",
  "units": {"length": "m", "mass": "kg", "time": "s"},
  "bodyProfile": "layer1-validated",
  "generator": {"name": "rungWall", "version": 1, "seed": 42,
    "parameters": {"heightGap": 0.25, "lateralGap": 0.40}},
  "materials": [{"id": "lowFriction", "staticFriction": 0.15,
    "dynamicFriction": 0.15, "frictionCombine": "Average",
    "bounciness": 0.0, "bounceCombine": "Average"}],
  "objects": [
    {"id": "ground", "type": "box", "size": [4.0,0.2,4.0],
      "pose": {"position": [0.0,-0.1,0.0], "rotation": [0,0,0,1]},
      "motion": "static", "massKg": null, "materialId": "lowFriction",
      "graspable": false},
    {"id": "rung0", "type": "box", "size": [0.5,0.1,0.25],
      "pose": {"position": [-0.2,0.95,-0.075], "rotation": [0,0,0,1]},
      "motion": "static", "massKg": null, "materialId": "lowFriction",
      "graspable": true, "surfacePolicy": "autoBoxTop"},
    {"id": "platform", "type": "box", "size": [2.0,0.2,1.5],
      "pose": {"position": [0.0,1.9,0.75], "rotation": [0,0,0,1]},
      "motion": "static", "massKg": null, "materialId": "lowFriction",
      "graspable": true, "surfacePolicy": "autoBoxTop"}
  ],
  "start": {
    "torso": {"position": [0,0.4,-0.4], "rotation": [0,0,0,1]},
    "leftHand": {"position": [-0.3,1.15,-0.05], "rotation": [0,0,0,1]},
    "rightHand": {"position": [0.3,0.95,-0.05], "rotation": [0,0,0,1]}
  },
  "goal": {"frame": "structure", "center": [0,2.6,0.6],
    "size": [0.8,0.4,0.6], "dwellSeconds": 0.3, "maxTorsoSpeed": 0.5},
  "validation": {"status": "unvalidated"}
}
```

该例仅说明格式，故意未列齐中间横档，不能当作已通过可解性验证的完整关卡。程序化生成器与玩家编辑器都输出 objects/start/goal；generator 对手工结构可为 null，不用 seed 重建来替代保存实际物体。

对象类型首批支持 box；后续 sphere/capsule/convexMesh 扩展需版本和形状专用校验。静态物体无 Rigidbody，massKg=null；dynamic 必须 massKg>0，不能用 mass=0 表示静态。kinematic 预留但首批加载应明确拒绝，不能默默改成 static。动态非凸 MeshCollider 不进入首批范围。材质必须引用存在的 ID，每个 Collider 显式分配，初期统一静/动摩擦 0.15、Average、弹性 0；不提供依赖 Unity 默认摩擦的缺省分支。

Box 的顶面/顶边由尺寸和运行时当前旋转，按相对重力的法线判定自动计算；倾倒后重新求顶面，不保存过时的世界顶面标签。边缘法线阈值、接触与上方侧判定沿用已验收身体语义。非基本形状以后可添加物体局部标记，加载时转换并验证；不把人工标记扩散到 Box。

导入校验：版本已知、ID 唯一、所有数值有限、尺寸/质量合法、材质引用存在、起点不穿透且手臂初始长度合法、目标有正体积、零缩放/未知类型拒绝。对场地范围、物体数、质量和最薄碰撞体设置产品上限（待确认）；报错包含 JSON 路径与对象 ID。未识别的主版本不得静默解析。不要从 JSON 加载任意脚本、资产路径或可执行代码。

### 2.2 验证记录与快照

validation 记录 schema/generator/body/controller 版本、输入内容 hash、Unity 与 solver 配置摘要、seed、落定指标、可解性试验条件/结果和原因。它是派生缓存；结构或身体版本改变即失效。保留玩家原始摆放姿态，另存 settledSnapshot（物体 ID→落定姿态和初速度），训练/回放选择明确的快照并清零速度。不得自动用落定结果覆盖原稿。

## 3. 程序化生成与难度

### 3.1 使用本轮证据

[扫描报告](LAYER2_SOLVABILITY.md)覆盖 h=0.15–0.60、s=0.20–0.80、步长 0.05，共 1040 次尝试。h≥0.35 的所有已测横距均 8/8；h=0.20–0.25 时 s≤0.30 全失败，较宽横距反而成功。因此难度不能只用“越小越容易”的单标量映射。

首批静态生成从 (0.25,0.40) 基准开始，候选池为已测成功的 h=0.20–0.40、s=0.35–0.60 离散组合。连续抖动、非交替路线、不同横档尺寸或动态箱子均需重新验证，不能继承这张热力图的成功标签。当前扫描每关四横档，平台高度随 h 变化；尚未隔离路程长度与单步难度。

难度参数显式分开：高差、横距、横档宽/厚/深、路线长度、绕行障碍、初始位姿扰动、可动物体比例/质量/支撑面。初期锁定后四类，只对一种参数做实验。保持最薄实体 0.10 m，先做几何净空过滤：不仅判断肩到目标距离，还验证撤离、抬高、插入路径中半径 0.10 m 手球及躯干包围体的碰撞。路径图可用抓点顶面/边缘候选作为节点，可达边作为启发式，身体公开接口脚本试爬作为成功见证。

失败结构分为输入不合法、未落定、控制器未证实可解、确认可解。脚本失败时保留种子/快照/轨迹和诊断，不把它直接标成物理不可能；可重采样以满足训练课程，也保留待人工/替代控制器复核队列。限制生成尝试次数，耗尽时返回明确错误，不无限重试。

### 3.2 落定模拟（建议验收阈值，尚未实测）

在隔离 PhysicsScene 的验证副本中实例化结构，不放角色，使用与训练相同固定步长/重力/材料。先几何过滤显著穿插，然后模拟至少 3 s，最长 10 s。最后连续 1 s，每个动态刚体要求 |v|<0.02 m/s、|ω|<0.05 rad/s；采样姿态，质心位移漂移 <0.01 m，角漂移 <1°。明确区分休眠与唤醒检测，不能以 IsSleeping 单独证明受载稳定。

初始到落定净位移 >0.05 m 或倾角改变 >5° 时记录“发生重排”，决定是否接受落定后的另一个结构，而非装作原始搭建已稳定。跌出结构边界、持续滚动/摆动、严重穿透、NaN、关节异常和达到时限均失败。阈值需用稳定堆叠与故意不稳定反例标定，不能视作现有测试已通过。

空载落定后再检查起点和目标净空、抓点法线/高度、脚本可达性。动态结构另做单手约 118 N 静载与动作载荷探针测试：空载不倒不代表角色悬挂不倒。保存峰值速度、位移、倾角和断裂事件。禁止用偷偷改成 kinematic、世界固定或增大摩擦修复不稳定结构。

## 4. 动态抓点设计

### 4.1 连接与表面变化

当前身体会拒绝动态抓点，本轮保持该逻辑。未来获准后，沿用接触/速度/可抓层/同场地/几何顶面准入与 false→true 重新武装；查询 Collider.attachedRigidbody。真正静态物体 connectedBody=null；动态箱子连接其真实 Rigidbody，锚点分别由同一世界接触点变换到手和箱子的局部坐标。不得把动态物体抓握做成世界固定，不在抓住时瞬移或冻结箱子。

Box 转动后新抓握候选按当前姿态重新识别顶部；已成立的关节保持原局部锚点，不把手吸移到新的顶面。现有握点随物体运动，倾倒本身并不自动生成新抓握。是否因表面倾斜强制松手是待定规则，初期建议只影响新准入，已抓握靠断裂/主动释放决定。

### 4.2 承载、倾倒和断裂

身体重约 12×9.81=117.72 N；支撑箱自重与角色抓握载荷同时进入接触求解。静态悬挂并不意味着手臂一直主动输出 117.72 N，肩部被动约束可以承载，峰值负载需分开记录。

箱子是否倾倒取决于支撑多边形与外力矩。简化例：质量 10 kg、底宽 0.40 m，居中静止时绕底边恢复力矩约 10×9.81×0.20=19.62 N·m；若约118 N 的水平载荷施于高0.40 m处，倾覆力矩约47.2 N·m，可能先倾倒而未触发握点断裂。这个估算不能替代多接触的模拟，且“箱子至少10 kg”不等于可承载角色。抓住悬空箱子双方一起落下是合法物理结果。

保留抓握 breakForce=900 N / breakTorque=90 N·m；肩部连接仍不可断裂，仅记录峰值。不能用主动450 N解释所有关节冲击上限。关节断裂后清理逻辑占用，冷却0.30 s，必须先 false 再 true；主动松手冷却0.20 s。箱子与手质量比、碰撞模式、solver 调整仅限受审阅配置，禁止改全局物理参数。

逐步事件/失败区分：GripBroken（力/力矩）、CandidateRejected、SupportLost、ObjectTipped、ObjectOutOfBounds、BodyFell、Timeout。ObjectTipped 是诊断事件，是否结束回合取决于任务，不能所有倾倒都判失败。新结构通过还需验证两个手连接同一个动态箱子/不同箱子的闭环、释放/断裂重入、重置无残留连接、跨场地拒绝与运行中销毁物体。动态抓点必须通过这些专项后才允许进入课程。

### 4.3 接口与守恒验收

未来身体继续是唯一施力与建关节主体，控制器不获可写 Rigidbody 引用。GetLoadState 需分别返回主动命令力、关节约束反力/力矩、采样物理步、坐标系和峰值；事件携带 arenaId/handId/objectId/step。肩部扭矩预算和躯干旋转开关单独评审，非径向内力必须保留反力偶补偿。自由落体质心/角动量、动态箱子抓握后系统动量、非冻结旋转和双手闭环都要有独立反例测试，不能只看脚本爬通。

## 5. 玩家搭建工具

建议为 Unity 内运行时搭建模式（待确认交付形态），与试玩互斥：编辑时暂停角色和模拟；调色板选择 Box/静态或动态预设，鼠标地面/物体表面放置，半透明 ghost 显示尺寸、碰撞和支撑。选择后用移动/旋转/尺寸工具，网格0.05 m、旋转15°作为可关闭初值；质量与材质从明确预设选择，不允许隐藏默认材质。Box 顶边自动显示，无需人工涂抹抓点。

界面支持多选、复制、删除、撤销/重做、对象ID和层级列表、起点与目标区域编辑。对象重叠、越界、起点穿透和不合法参数即时提示；试玩前执行静态校验与落定验证。试玩通过统一结构加载和身体 ResetBody 开始；手动与脚本均使用同一身体接口。退出试玩恢复编辑原稿，不把被推倒后的状态静默写回。

保存流程：编辑→静态校验→保存草稿→可选落定/脚本验证→展示逐项结果→保存带验证记录版本。保存到 `structures/<id>.json`，先写同目录临时文件并验证可重新解析，再原子替换；保留原稿与可选 settledSnapshot、缩略图。加载未知主版本或引用缺失给出明确错误，不丢物体后继续。玩家结构和程序生成结构都经过同一校验器；分享文件不包含可执行内容。

## 6. 实施顺序与待决定项

1. 确认 JSON 字段、搭建工具平台/交互和物体数/尺寸/质量限制；实现静态往返保存与错误提示。
2. 对已测成功的静态组合做生成器、落定验证反例、公开接口脚本验收；扩充随机种子和布局测试。
3. 经单独确认后扩展动态抓点与事件/负载接口，完成闭环、断裂、守恒专项；不混入静态扫描结论。
4. 进行搭建→保存→加载→试玩→验证报告的端到端验收，之后再讨论第3层训练。

需要用户决定、已跳过实现：运行时搭建还是 Editor 工具；首批是否开放动态物体及质量/物体数上限；倾倒是否算特定任务失败；运动学抓点与旋转解锁是否进入第2层首批；是否批准替代抓点/恢复路径实验；第3层 PPO pilot 和训练预算。上述选择不阻塞本轮静态准备交付。
