# Layer 3：示范状态初始化（只开启示范出生）

【数据】为有测量支持的结论；【推断】为未直接测量的判断，并注明如何验证。

## 1. 设置

| 项目 | 值 |
|---|---|
| 唯一变量 | 开启示范出生（`--climb-snapshot-library`），其余与`climb_target_incremental.yaml`相同；配置为`config/climb_demo_init.yaml` |
| 出生分布 | 50%地面、50%示范。示范部分：S1a 17.5% / S1b 17.5% / S2 35% / S3 30% |
| 状态库 | `results/climb-snapshots-v2/library.jsonl`：128条专家轨迹，S1a 180 / S1b 521 / S2 1282 / S3 1687。sha256见[验证摘要](data/climb-snapshot-verification/summary.json) |
| 训练 | seed 2026/2027，各5M步，CPU，4个实例，`scripts/run_demo_init.py`；代码为8960c2e |
| 评估（同原协议） | 1M/2.5M/5M checkpoint，确定性，每个200回合。地面起点沿用原评估；S1a–S3起点由`run_demo_init_stage_eval.py`逐阶段运行，每个回合都从该阶段出发 |
| 对照基线（每阶段200回合，与checkpoint无关） | `hold`：连续动作为零，即目标不动；每只手的抓握请求等于其当前是否抓住，已抓的保持，未抓的不去抓。`random`：均匀随机动作。脚本`run_demo_init_baselines.py` |
| 顺序 | 训练、地面评估、阶段评估、基线依次运行，互不并发。00:18开始，01:51全部完成 |
| 数据 | [climb-demo-init](data/climb-demo-init/)：summary.json、per_seed.csv、各评估的metrics.json/runtime.csv、TensorBoard标量和日志 |

口径：
- 新抓握：回合内新建立过抓握，快照起始时已抓住的不计。
- 持有抓握：回合内任意时刻有手处于抓握状态。
- 一级/二级/成功：沿用Agent判定，成功即记二级（见[LAYER3_SNAPSHOT_DESIGN.md](LAYER3_SNAPSHOT_DESIGN.md) §8.7）。
- 起始已一级：快照的账本中一级已为真。S3快照全部如此，所以S3的一级率没有意义。
- 训练中没有逐回合记录抓握，因此训练期的趋势只含一级、二级和成功。

## 2. 出生机制本身正常

- 【数据】示范出生占比：2026为50.1%（8,451回合），2027为50.0%（8,430回合）。各训练阶段实际恢复率为0.49–0.54。
- 【数据】隔离0/3670；拒绝、缺失、观察不一致的告警均为0。
- 【数据】RewardProgress首次非零：2026在第40,000步，2027在第30,000步，远早于1M，因此没有触发"1M后仍为0"的告警。
- 【推断】这个非零几乎全部来自S2/S3出生的+0.1进度奖励，见第3节；它不说明策略学到了什么。

## 4. 结论

1. **能否从地面串联完成：不能。** 【数据】两个seed各5M步，地面起点在训练期（约8,400回合）和确定性评估（6×200回合）中一级都为0，与无示范对照（incremental s2026/s2027，同样为0）没有差别。
2. **示范出生带来的登层几乎全是"白送"的。** 【数据】S2的一级率，零动作hold基线就有97%，训练策略最高97.5%；S3的一级是起始状态自带的。训练中RewardProgress非零，主要来自这两类出生。
3. **策略在S2上学到的只是"不打乱"。** 【数据】S2训练期的一级率从73%（2026）/89%（2027）升到约94–95%，接近但没有超过hold的97%；random为75.5%，说明随机动作会把身体扰下来。
4. **两个真正的技能缺口：S1b→一级（撑起）和S3→二级（转换）。** 【数据】两者的一级/二级均为0，或接近基线；唯一的例外是s2027 5M S1b的6%。
5. 【推断】原因是这两段的奖励稀疏程度并没有因为示范出生而改善：
   - S2的+0.1几乎与动作无关（hold就能拿到），只提供"别乱动"的梯度。
   - 从S1b到一级，专家轨迹中需要约1.0–1.5s持续正确的发力，才能拿到同一个+0.1。
   - S3需要完成松开→重武装→够→抓→撑的完整序列，才有+0.1和+1。
   - 验证方法：按"快照距离一级/二级事件的剩余时间"分档，统计各档的成功率，看是否存在随距离急剧下降的边界。
6. 【推断】抓握期的力向：本轮有两个1M checkpoint抓握期躯干受力向上（+100–105N，此前incremental多为向下），但到2.5M/5M消失，与此前"checkpoint间漂移"的现象一致；不足以说明方向问题已解决。

## 5. 建议（待确认）

- 每次只改一个变量。可选的下一步：
  1. **把示范起点向"距离奖励更近"的方向细分。** 例如S1b/S3按距事件的剩余时间加权，并把S2中距一级很近、hold就能拿到的快照降权，把采样预算让给策略真正缺的两段。
  2. 保持出生分布不变，**延长训练**（例如20M步），检验s2027 S1b末段的弱信号能否增长。
- 主评估继续只看地面起点；阶段起点和hold/random基线作为固定的诊断项。
