# 第3层：课程C2设计（2026-11-11，已批准）

只写设计，不实现。【数据】是有测量支持的结论，【推断】是设计判断。依据见[LAYER3_CURRICULUM_C0C1.md](LAYER3_CURRICULUM_C0C1.md) §3–§6。

## 0. 设计前提：台阶高度按"有效上升"计算

- 【数据】特征`maxRise`会漏掉叠箱形成的高台阶：下面的箱顶被上面的箱盖住，就不能站立。v2 Hard中26/60个结构的第一级就是这样，实际要站上1.0m的台面，`maxRise`却报0.5m（C0+C1报告§6）。
- **定义**：沿几何检查路线（`feasibility.route`），相邻两个可站立表面的顶面高度差，叫"有效上升"。"站立级数"是路线上的上升次数。
  - 【数据】v2全部1,073个结构中（训练893，评估180），有效上升只有两类：约0.5m，以及0.95–1.05m。没有中间高度，因为箱子高度只有0.5m和约1m两种。
  - 所以"台阶高度区间"只分两档：**低**（<0.9m，实际都是0.5m）和**高**（≥0.9m，实际0.95–1.05m）。
- 【推断】这个定义只看几何和几何检查的路线，不看任何控制器或策略的结果，可以用来分层。
  - 路线是几何检查选出的一条链，结构上可能还有别的路线。这个局限要披露。

## 1. 训练池中高台阶的比例

**目标**：C2中，含有效上升≥0.95m的结构占全部回合的**60%**。C1中这个比例约为2%（7/254 × 75%）。

| 来源 | C2中每回合的抽取概率 |
|---|---|
| 训练两级台阶（地面或示范起点，与C1相同） | 0.25 |
| A：低→低（C1训练结构，加上Standard中的同类结构） | 0.15 |
| B：高→低（第一级高） | 0.20 |
| C：低→高（第二级高） | 0.20 |
| D：高→高 | 0.20 |

层内均匀抽结构。高台阶的合计是B+C+D=0.60。

**理由：**
1. 【数据】评估集需要高台阶：v2 Easy中13/60、Standard中36/60、Hard中59/60的结构至少有一个有效上升≥0.95m。不学会高台阶，Standard和Hard就上不去。
2. 【数据】比例太低时，有的种子学不会。C1中高台阶只占2.8%，s2026训练末期在1.05m结构上0/224成功，评估中这类结构全部0/20；s2027在同样的比例下学会了。
   - 【推断】2.8%对有的种子够，对有的不够，提高比例是降低种子依赖最直接的做法。
3. 保留40%的低→低（两级台阶0.25加A 0.15）防止遗忘。C1的能力目前接近100%（C1验证99.8%和100%）；如果完全不再抽到这些结构，可能退化。
4. B、C、D三种高台阶位置权重相同。在800万步中，每种大约160万步。
   - 【数据】它们的失败模式不同：s2026在B上能站上高箱，但上不了后面的0.5m；在Hard的C、D型中，第一级就失败。所以三种都需要足够的样本。
5. C2只改结构分布这一个变量。3级以上的结构（F层）留给C3，不在C2中引入，这样C2的结果能归因于高台阶。
6. **C2不处理周围环境的影响，预期对Hard的提升有限**（2026-11-11确认）。
   - 【数据】Hard诊断（C0+C1报告§6）显示，同样的单个高箱：在Easy中两个种子都是20/20到一级，在Hard中只有0.00和0.17。差别在于周围箱体更多（外露顶边10.7 vs 5.4）。
   - 【推断】周围箱体的布局影响策略行为。C2只含两层结构，不改变周围环境。
   - 所以预期C2对v2 Hard的提升有限，Hard只报告、不作门槛（§4.2）。周围环境的多样性留给C3，作为单独变量。
   - C2训练前，先用带诊断观察器的Player对C0+C1两个checkpoint补测v2 Hard（§5第4条），验证这一推断。

## 2. 新的冻结分层集

### 2.1 分层

按站立级数和有效上升的高低分层，只取2级（C2用）；F层冻结后留给C3。

| 层 | 站立级数 | 上升模式 | v2训练池中的结构数 | Python聚类簇数¹ | 来自的档 |
|---|---|---|---|---|---|
| A | 2 | 低→低 | 364 | 186 | Easy 274，Standard 90 |
| B | 2 | 高→低 | 107 | 106 | Easy 7，Standard 26，Hard 74 |
| C | 2 | 低→高 | 176 | 156 | Standard 103，Hard 73 |
| D | 2 | 高→高 | 95 | 87 | Standard 31，Hard 64 |
| E | ≥3 | 全低 | 8 | 8 | 太少，不作为一层，只记录 |
| F | ≥3 | 至少一个高 | 131 | 131 | 留给C3 |

¹ Python聚类（`scripts/analyze_zero_shot.py`）不含镜像等价，所以簇数是上限。冻结时用C#的`ClimbGeneratorV2Sets.Linked`（含镜像），簇数会更少。
- 【数据】在C1上，Python是130簇，C#是85簇，比例0.65。
- B、C、D、F中几乎每个结构自成一个Python簇。镜像合并最多让簇数减半，所以C#簇数估计为：A约120，B 53–106，C 78–156，D 44–87。实际数量以冻结时为准。
- **更正（冻结后，【数据】）**：C#簇数为A 132、B 104、C 149、D 85（见§6）。B、C、D几乎没有因镜像合并，按"上限的一半"估计偏低；A的合并也比C1上的比例少。

**来源**：只用v2训练池（`structures/box-stacks-v2/train`），其中的Standard、Hard部分至今没有用于训练。
- v2评估集（§16的完成标准用集）不进入分层，继续保留作为最终测试，不参与模型选择。

### 2.2 层内按簇划分训练与评估

- 每层固定留出**30个簇**作为C2评估，其余用于训练。
  - 如果某层C#簇数不足75（留出30个后训练少于45个），改为留出40%，并在报告中给出实际n。
  - 留出后，如果评估簇少于25个，这一层只报告、不进入验收，并单独列出（预计只可能发生在D层）。
- A层的评估部分**包含C1验证集的全部17个簇**（它们已经从训练中留出），另外再随机留出13个簇，合计30。C1验证集仍然不进入训练。
- 用固定seed洗牌后划分，与C1相同（§17.2的做法），不看任何控制器或策略的结果。
- **单箱**（12个，6簇）只作为C0内容，不进入C2。
- 冻结后写入`structures/curriculum-v2/`，包括每个结构的sha256、层、簇和路线上升序列。冻结工具拒绝重复冻结（同C1）。
- 预计的C2评估规模：A–D各约30个簇，结构约30–60个，总计约120–200个结构。

**D层不足时的补充方案（2026-11-11决定：暂不做）**：只有当C2训练中D层明显落后于B、C，且怀疑是数据量不足时，才作为单独实验。原方案：用v2生成器，以新的不相交seed区间，按同样的规则（落定检查、去重、与评估集不相连）补充生成。
- 【数据】v2训练池中，D层的产出约为Hard 64/3023个seed、Standard 31/918个seed。
- 补3000个Hard seed，预计能多出约60个D层结构。

## 3. 课程安排：从C0+C1继续，还是从头训练

| | 从C0+C1的8M checkpoint继续（`--initialize-from`） | 从头训练（C0→C1→C2） |
|---|---|---|
| 计算 | 每个种子800万步，约1小时 | 每个种子约1600–2400万步，约2–3小时 |
| 归因 | 结果依赖C0+C1的历史。两个种子起点很不一样：s2026在高台阶上完全失败，s2027已经会了。 | 归因更干净，课程整体可以复现。 |
| 回答的问题 | "已有的策略能否通过加高台阶补上缺口" | "C0→C2整个课程能否稳定地产生高台阶能力" |
| 风险 | 策略可能已经形成固定的动作习惯。【数据】熵从2.81降到2.21（s2026）和1.94（s2027），还没有塌缩，所以仍有探索空间。观察归一化统计会带入。 | 计算多，各阶段的步数安排需要重新确定。 |
| 实现 | `mlagents` 1.1有`--initialize-from`（`trainers/cli_utils.py`，【数据】）。【推断】步数从0开始计，归一化器随checkpoint载入，实施前要查包源码确认。 | 与C0+C1相同的运行器，只加一个阶段。 |

**建议：从C0+C1的checkpoint继续训练，作为C2的主线。** 两个种子各800万步，配置与C0+C1相同，只改结构池和抽取概率（§1）。
- 理由：
  - 计算是从头训练的一半以下；
  - C1能力已经验证到接近100%；
  - s2026正好可以检验"加大高台阶比例，能否补上缺口"。
- 如果早停触发，或者出现遗忘（§4），下一步再从头训练C0→C2，作为第二个实验，不同时跑。
- 依赖（已解决，2026-11-11）：严格对照（C0+C1报告§8）显示，只训练两级台阶800万步，泛化明显低于C0+C1：
  - 【数据】C1验证上，课程比对照高29和57个百分点；v2 Easy上高15和56个百分点；逐结构没有反例。
  - 【数据】两个对照种子在Easy高箱结构上都是0/20。
  - 所以课程形式的贡献成立，C2继续用课程形式。

## 4. 早期止损与验收标准

### 4.1 早期止损（每个种子单独，按训练日志中的地面起点回合判定）

1. **学不会**：C2开始后200万步时，如果B、C、D中任何一层，最近50万步内地面起点成功为0，就停止该种子并汇报。
   - 下一步实验候选：在高台阶结构上补录示范状态库（同C1的止损方案）。
2. **遗忘**：每100万步检查一次。如果两级台阶或A层的地面起点成功率（最近50万步）低于85%，就停止该种子并汇报。
   - C1末期训练中，两者都在97%以上。85%留出了随机动作训练的余量。
- 两条都用TensorBoard的分层标量和逐回合CSV双重核对，同C0+C1的做法。

### 4.2 验收（在看到任何C2结果之前确定）

在C2评估集（§2.2的留出簇）上评估：Player build，确定性动作，地面起点，每个结构20回合。
- 统计单位是结构，按簇做bootstrap区间。
- 只计算通过几何检查的结构，同时报告被排除的数量和脚本控制器的完成率。
- **每个种子分别达标**：

| 项目 | 标准 |
|---|---|
| B、C、D每层 | ≥70%，且95%区间下限≥60% |
| A层（不退化） | ≥95% |
| 训练两级台阶，200回合 | ≥90% |
| v2 Easy（§16 Easy标准） | ≥80%，且下限≥70% |
| 每层Fall+出界 | ≤5% |

- **只报告，不作门槛**：v2 Standard、v2 Hard、F层，以及各层的失败阶段和形状分类。
- 70%的理由（【推断】）：s2027在C0+C1后，v2 Standard中高台阶结构的成功率是0.46–0.63（按`maxRise`）。C2专门训练高台阶，应当明显高于这个水平；§16的Standard线是60%，C2的单层门槛应当高于它。
- 如果补测诊断批准（C0+C1报告§6.3），同时报告抓握尝试次数、被拒原因、躯干最大高度，用来检查§6的推断。

由`Tools/Climb/Freeze Curriculum C2`（`scripts/freeze_curriculum_c2.ps1`）在worktree中生成。`pools.json`是训练用的课程文件（版本2），`strata.json`记录每个结构的层、簇、路线上升序列和划分。

- 簇在所有非单箱训练结构之间统一计算（含镜像），**没有一个簇跨两层**，所以任何层的评估簇都不会出现在训练中。

  - 27个C1验证结构全部在A层评估中（17个簇）；

- **冻结中遇到的一个问题与处理**（2026-11-11 已确认）：
  - C1的簇只在Easy两层结构之间计算。加入Standard结构后，有Standard结构同时与一个C1验证簇和一个C1训练簇相连，把两边并成了一个簇。
  - 处理：这样的簇中，C1结构保持原划分，**非C1结构不进入C2的训练和评估**，然后重新计算簇，直到没有冲突。
  - 结果：排除3个，全是A层的Standard结构（`stack2-standard-100082`、`100461`、`100760`），在`strata.json`中标为`excluded-bridge`。
  - 排除的数量和原因写在`strata.json`的`excludedBridgeNote`字段中（由冻结脚本生成；重新冻结验证：`pools.json`逐字节相同，`strata.json`只多这一字段）。C2结果报告中同样写明。
  - 【推断】这是最保守的做法：这3个结构与C1训练结构几乎相同，不能用于评估；又与C1验证结构几乎相同，用于训练会污染A层评估。
- 抽取比例（所有回合）：两级台阶0.25，A 0.15，B、C、D各0.20。
