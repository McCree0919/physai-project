# 箱子堆叠生成器与抓握遮挡验收

## 本轮交付

设计先更新于[LAYER2_DESIGN.md第10节](LAYER2_DESIGN.md)，随后新增箱子堆叠管线。原StaticWallGenerator、原扫描策略和回归测试保留；身体仅新增一条抓握净空准入调用，尺寸、质量、臂长、力、PD、旋转约束与关节参数均未修改。开发仍在layer2，main未更新。

核心文件：`BoxStackGenerator.cs`、`BoxStackSettlement.cs`、`BoxClimbSmokeController.cs`；JSON和加载器复用Structures程序集。`GripClearance.cs`实现实际候选点上方的净空查询。预设Step/Tall/Wide可供未来运行时UI复用，本轮不实现UI或运行时动态抓点。

## 物体与构造

| 预设 | 基础尺寸 x×y×z（m） | 固定质量 |
| --- | --- | ---: |
| Step | 1.20×0.50×1.20 | 15 kg |
| Tall | 1.20×1.00×1.20 | 25 kg |
| Wide | 1.80×0.50×1.20 | 25 kg |

程序生成取0.95/1.00/1.05的尺寸缩放，再将尺寸/接触面吸附0.05m网格；量化后各轴比例不保证完全一致。Wide允许90°朝向。每结构最多32物体，固定地面为基础；箱子按台阶、塔、轻/多悬挑及分离侧塔间隙组合。JSON显式记录movable=false、settleAsDynamic=true、presetId和质量；旧静态JSON缺少新字段仍按旧固定支点解析。加载后仅角色的3个刚体保持动态，箱子均冻结为静态。

## 动态落定与60个候选

每档固定seed=0..19，各20个候选，逐个真实动态落定，不调用脚本、不按成功率过滤、不补抽。通过后才将落定位姿导出到`structures/box-stacks/`，共59份。最高层顶面目标的中心高出顶面0.60m，区域0.60×0.40×0.60m。

| 难度 | 尝试 | 通过 | 通过率 | 拒绝原因 |
| --- | ---: | ---: | ---: | --- |
| Easy | 20 | 20 | 100% | 无 |
| Standard | 20 | 20 | 100% | 无 |
| Hard | 20 | 19 | 95% | CollapsedOrRearranged 1次 |

Hard seed=3出现实际倒塌：tier1净位移约1.294m、旋转90°；tier2约2.528m/149.82°；tier3约3.598m/180°。最终虽然停止并休眠，仍因远超0.05m/5°拒绝，未将倒塌后落稳误当原结构稳定。拒绝候选完整JSON已[归档](data/box-stacks/rejected/hard-3.json)。

落定规则：隔离PhysicsScene，固定地面，所有箱子有真实质量、重力和碰撞；至少3s、最多10s；最后连续1s速度<0.02m/s、角速度<0.05rad/s、窗口漂移<0.01m、角漂移<1°。相对输入净位移≤0.05m、转角≤5°，无越界/严重穿透，之后做粗可达检查，再以静态物体加载。

通过样本的最大净位移：Easy约0.0031mm，Standard约1.72mm，Hard约11.12mm；最大转角分别0°、0°、0.3334°。终端速度均0，最终30/30、57/57、85/85个箱体处于正常休眠。睡眠只是另列状态，不作为唯一通过条件；倒塌反例说明检查了输入到落定的姿态变化。

新箱子允许≤5mm的接触求解穿透，实测通过样本最大约3.695mm；原横档静态验证继续使用2mm。初版生成曾因缩放后箱底未对齐地面而拒绝，现已按实际尺寸对齐支撑面；没有改变物理参数或用脚本补救。

## 特征分布

下表为20个输入候选的特征范围；通过样本的落定后分布单独归档，避免将拒绝输入和通过后的姿态混为同一统计口径。

| 特征 | Easy | Standard | Hard |
| --- | --- | --- | --- |
| 最高箱的支撑堆叠层数 | 1–2 | 2–3 | 3–4 |
| 全场不同顶面高度数（含侧塔） | 1–2 | 2–4 | 4–5 |
| 单箱最大竖直面高度（m） | 0.50–1.05 | 0.95–1.05 | 1.00–1.05 |
| 悬挑数量 | 0 | 0–2 | 2–3 |
| 最大悬挑长度（m） | 0 | 0–0.25 | 0.125–0.40 |
| 最大间隙宽度（m） | 0 | 0–0.10 | 0.20–0.40 |
| 暴露顶边抽样数量 | 4–5 | 5–8 | 11–12 |
| 总高度（m） | 0.95–1.05 | 1.45–2.05 | 1.95–2.55 |

支撑层数每档各一半落在两个值：Easy的1/2层各10个，Standard的2/3层各10个，Hard的3/4层各10个。Easy无间隙；Standard为13个无间隙、7个0.10m间隙；Hard的0.20/0.25/0.30/0.35/0.40m各4个。

粗图以落定后几何为准，相邻可抓顶边竖直差≤1.50m、距离≤1.80m，从角色起点到最高顶面存在连接；通过样本的粗图最少跃迁数分别1、1–3、2–3。它是几何下界，不代表必须执行的翻越动作次数，更不是脚本可解性。原始输入在边界上的浮点/微小接触位移可能改变粗图连通性，不用输入粗图标签替代落定后的准入。

暴露顶边数量使用每条顶边中点的保守净空盒抽样，不是连续边段长度；maxUntoppedRise表示全场暴露顶边高度序列的最大间隔，不宣称精确描述每个方向的竖直面。实际抓握对具体接触点用原生胶囊查询，覆盖区域拒绝，暴露区域允许。模板化生成的60样本不是泛化能力证明。

完整[输入特征与直方图](data/box-stacks/summary.json)、[逐种子输入/落定后CSV](data/box-stacks/features.csv)、[动态验证逐箱数据](data/box-stacks/trials.json)均已保存。

## 冒烟与回归

**batchmode编译零错误，PlayMode 42/42通过**：保留前轮32项，新增10项。独立Windows Player编译/构建也通过。新的身体准入测试覆盖局部覆盖、完全覆盖、0.12m窄缝拒绝、0.30m净空允许；所有横档墙测试仍通过。

| 固定关卡 | 场地数 | 成功 | 用时（模拟秒） | 到达时躯干中心示例（场地局部m） |
| --- | ---: | ---: | --- | --- |
| 单个Tall箱，顶面1.00m | 16 | 16/16 | 2.60 | (0.00006,1.45081,0.52854) |
| Wide下层0.50m + Step上层1.00m | 16 | 16/16 | 4.94–5.02 | (0.00005,1.45056,1.12834) |

场地平移并带0/±15°旋转。两级台阶控制器实际经过第一层撑起、落稳释放、重新武装、再抓第二层，没有直接跳过第一层。终点要求躯干中心在最高层区域连续0.30s、速度<0.50m/s。控制器只调用公开身体接口，无额外施力或Transform移动。

单箱首轮曾因沿用横档墙手部出生位置而被净空检查拒绝；箱子关卡手的出生z改为-0.15m后通过。身体参数、原横档出生点和控制策略均未为此修改。两级台阶没有失败，不存在通过调身体参数掩盖失败的情况。

两份Editor生成的保存场景重载后也成功，约2.60s和5.06s。证据：[测试XML](data/box-stacks/tests.xml)、[逐场地姿态/速度/抓握数据](data/box-stacks/smoke_metrics.json)。

## 使用

先关闭Unity编辑器：

```powershell
.\scripts\generate_box_stacks.ps1
.\scripts\test_layer2.ps1
conda run -n mlagents python scripts/analyze_box_stacks.py
```

编辑器菜单 **Tools → Structures → Build Box Smoke Scenes** 生成两个固定场景；打开`Assets/Scenes/BoxSingleSmoke.unity`或`Assets/Scenes/BoxStepsSmoke.unity`并Play即可观察。**Tools → Structures → Generate Box Stack Samples** 运行60候选实验。需要显式材质资源时，先执行已有的Build Static JSON Demo菜单。

本轮未实现运行时搭建UI、运行时动态抓握、策略训练或“换身体”评估；默认身体能力保持不变。main不合并，本轮成果留在layer2。
