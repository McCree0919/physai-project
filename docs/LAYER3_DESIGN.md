# 第3层：多级攀爬学习设计

状态：用户已确认并补充修改。本轮实现无记忆Agent与正常底部出生的两级PPO校准试跑；不实现示范状态初始化、行为克隆或正式多种子实验。基线为layer2-static（7d0e149）；默认身体、物理材质与ProjectSettings保持不变。

## 1. 问题与实验假设

队友二维版本约45%的训练分布成功率、第二级转换困难、三级以上近0，作为任务背景，不能直接当本项目的评估结果。本项目脚本已在固定单箱和固定两级台阶各16场地成功，证明这两关可解；尚未证明所有随机结构、三级或更多关卡均可解。

主要学习假设是“到达一级后，稳定身体→释放旧支撑→false重新武装→将目标移向下一抓点→重新抓握→撑起”的长时序探索与信用分配困难，而非需要更强身体。保留横档墙作物理回归，训练与泛化评估以箱子堆叠为主。生成器只以物理稳定性和粗几何准入，绝不以专家脚本是否成功筛选结构。

第3层第一项实际运行是接口确认后的10–15分钟PPO短时试跑；用户已授权本轮实现和试跑。试跑通过后再展开完整课程和对照。

## 2. 动作空间与身体接口

### 2.1 首选：6维连续 + 两个二元离散分支

行为名建议Climb。固定物理步长沿用0.02s，每5物理步决策一次，即10Hz模拟时间控制频率。所有观测在统一的决策前时刻采集，动作从下一物理步生效；中间物理步维持命令，不能重复积分目标增量。

| 动作 | 维度/范围 | 映射 |
| --- | --- | --- |
| 左手目标增量方向 | 3维，各[-1,1] | 躯干坐标，向量范数裁剪到1，目标速度上限0.8m/s |
| 右手目标增量方向 | 3维，各[-1,1] | 同上 |
| 左手抓握请求 | 离散分支大小2：0/1 | SetGrab(Left,false/true) |
| 右手抓握请求 | 离散分支大小2：0/1 | SetGrab(Right,false/true) |

每次决策更新肩部相对目标 q←Project(q+0.8×0.1×a)，即最大0.08m/次；q为控制器持有的躯干坐标命令目标，不跟随实际手位置重新生成。投影到现有0.15–0.85m目标球壳，再通过SetHandTarget提交。身体仍执行原1.5m/s目标限速、PD和物理预算。归零动作表示保持目标，不是回中。目标初始化取ResetBody后当前手相对肩部位置，回合重置清除命令缓存，首版无循环记忆。

抓握请求是状态命令，不是每帧“切换”。持续1不重复创建关节；释放/断裂后遵守冷却及false→true重新武装。输出1表示希望保持/尝试抓握，0表示希望松开；策略必须在释放/断裂后显式输出0以重新武装，再输出1申请下一次抓握。持续1不会绕过重新武装规则；0在冷却中也可重新武装，但1仍须等待冷却。初版不加入“自动抓”“自动重新武装”或阶段机辅助，不添加直接躯干力、关节修改或Transform移动。除ResetBody回合管理外，只有SetHandTarget与SetGrab写身体；状态只读公开快照。

### 2.2 努力值先固定

首选将努力值从动作中去掉：自由手固定1.00，已抓手固定0.70，按公开Grabbed状态选择；仍经过身体原有努力值渐变。这复用成功脚本的力预算，不是增强身体。自由手40N、自重9.81N，最小悬空上行动作约0.245；支撑手315N对身体总重117.72N约有2.68倍静载量级，不能将该比值解释为所有姿态都可控。按第1层45°承载估算，u_min≈117.72/(450cos45°)≈0.37，固定0.70仍有约1.89倍力幅余量；自由手固定1.00约为克服自重阈值0.245的4.08倍。

固定努力值避免初期同时搜索“方向正确且力度足够”，但可能使精细制动困难。只有确认位置/抓握版本能学两级后，单变量比较：①固定自由1/支撑0.7；②两手统一0.7；③每手增加1维努力值，连续动作变8维，u=0.3+0.7(a+1)/2。第三项下限仍高于自由手重力阈值，但不保证支撑抬升；若使用真正[0,1]努力值，应独立报告低动作死区影响。不要一次同时改动作、奖励和身体参数。

## 3. 观察：327个局部浮点值

以躯干朝向为坐标系；局部几何范围固定，排除自身角色，只查询同场地环境。目标是任务提供的相对目标信标，允许看到方向和相对距离；除此之外不提供全局地图、结构ID、种子、难度标签、箱子列表、剩余层数、专家阶段或完整物体位姿。绝对Arena坐标、世界位置/朝向不进入策略。

### 3.1 本体与接触：65维

| 内容 | 维度 | 归一化/语义 |
| --- | ---: | --- |
| 躯干线速度、角速度 | 3+3 | 除以5m/s、10rad/s，裁剪[-1,1] |
| 重力方向在躯干坐标中的单位向量 | 3 | 不提供绝对yaw；即使当前锁旋转也保留接口 |
| 目标中心相对躯干的位置 | 3 | 除以固定6m、裁剪[-1,1]，不按每关总高度缩放 |
| 剩余回合时间比例 | 1 | [0,1]，本地时钟 |
| 每只手：位置相对肩部、速度相对肩部、当前命令目标 | 3+3+3 | 位置/目标除0.9m，速度除5m/s |
| 每只手：臂长比、当前努力值 | 1+1 | 臂长除0.9m；努力值[0,1] |
| 每只手：实际主动命令力向量 | 3 | 除以固定450N、裁剪；不虚构未公开的完整关节负载 |
| 每只手：Grabbed/GrabRequested/NeedsRearm、冷却 | 3+1 | 三布尔、冷却除0.3s并裁剪[0,1] |
| 每只手：候选存在/允许、相对接触点、法线 | 1+1+3+3 | 仅本地接触查询；无候选时几何字段为0，接触点相对手除0.9m |

身体13维 + 每手26维×2 = 65维。源码核查修正：GetHandState.TargetOffset实际返回身体滤波后的目标。本版按表观察控制器自己的命令q，避免隐藏增量积分状态；通常0.08m/决策小于身体0.15m/决策的滤波能力，但抓握切换重置时两者可能不同。因此不声称完全Markov；以后若研究额外观察滤波目标，可单独增加6维作消融，不偷偷修改327维合同。相对肩部速度由公开躯干线/角速度、肩位置与手速度计算。候选存在掩码由公开查询结果定义，不能暴露Collider ID；非法接触也可报告存在但Allowed=0。

### 3.2 局部几何：262维

选择射线与小高度图组合，初期不用体素。高度图便于感知落脚顶部，射线补充侧壁、悬挑和上方遮挡；单一顶视高度图会丢失下面的空腔。稠密体素计算/网络成本较高，留作后续独立消融。

| 感知 | 配置 | 维度 |
| --- | --- | ---: |
| 局部射线 | 肩部高度附近出发，yaw=-120°..120°每30°共9方向，pitch=-45°/0°/+45°，长度2m | 27×6=162 |
| 局部高度采样 | 躯干周围5×5网格，x/z为-0.8,-0.4,0,0.4,0.8m；由躯干上方1.5m向下查询3m | 25×4=100 |

射线每条输出hit、距离/2、命中法线的躯干坐标xyz、可抓取表面标记。该标记仅表示碰撞层/表面资格，不将侧面误标为当前可抓；实际准入仍由身体判断。

高度采样每点输出hit、相对躯干高度/1.5、法线与up点积、该命中点的局部抓握净空标记。只看查询到的第一表面，缺失时hit=0其余=0。净空标记采用与身体相同的半径0.10m/高度0.22m规则。查询不能穿透箱子读取被覆盖顶面，也不能用生成器对象列表补全地图。

合计65+162+100=327维。首版采用2×256前馈网络，不叠帧、不使用循环记忆。GrabRequested/NeedsRearm/冷却和命令目标显式观察用于表达当前控制状态。循环记忆128/sequence32仅作为后续独立对照，其他条件保持一致；本轮不实现。实施逐字段核验数量、坐标、掩码和数值范围。

## 4. 奖励与终止

### 4.1 首版奖励

| 事件 | 奖励 | 规则 |
| --- | ---: | --- |
| 最终成功 | +1.0 | 躯干中心在最高层目标区域连续0.30s，速度<0.50m/s；一次后结束 |
| 失败 | -1.0 | 掉落、不可恢复断裂、物体越界或超时，结束 |
| 时间成本 | -0.0002/决策 | 600次决策的60s回合最多-0.12；每决策结算一次 |
| 首次稳定登上更高支撑层 | +0.10/次，整回合总额≤0.30 | 使用下述一次性进展判定 |

初期不奖励手碰到物体、不奖励抓握次数、不直接奖励躯干瞬时高度、垂直速度或手到目标距离。不预设额外“到第二层”的特权指令。成功帧可同时结算一次合格层进展，但总进展上限不变。

稳定登层判定由本地向下探测/接触证据确认：躯干底部投影的中心与四角有支撑顶面，底面到顶面间隙≤0.08m，速度<0.25m/s持续0.30s。当前脚本到达时可双手仍抓住、身体悬在顶面上方约5cm，故不要求脚落地或强制松手。上方净空和真实支撑面积须通过，不能靠竖直壁侧擦触发。这里只读物理状态，不添加支撑力。

回合记录已奖励支撑与最高稳定支撑高度；只有稳定高度比旧纪录至少高0.20m，且该支撑未奖励，才发一次。初始地面不奖励，落回旧层再爬不再奖励；不按跨过多少高度刻度重复发奖。支撑ID只用于奖励内部去重，不作为观察；不使用生成器层号/总层数，也不按脚本路线设置奖励。

### 4.2 防止取巧

- 抓放、换手、NeedsRearm变化均不发奖；原地高频切换不能获益。
- 空中抬手、原地起跳或在同一支撑上悬吊刷高度不满足稳定登层；支撑高度取实际接触面，不取手高度。
- 两个同高箱子互换、跌落重爬、重置缓存漏洞不能重复结算。重置仅由环境管理器调用，并清理所有回合状态。
- 进展总收益≤0.30，小于终点1.0；停在中间层只会持续损失时间。检查“只刷进展不完成”的策略是否出现，而不是只看总reward。
- 初版不叠加另一个未论证的高度距离shaping。若稀疏学习仍失败，先看轨迹/阶段指标；势函数奖励另做单变量消融并处理终止势值，不能临时把成功标准放宽。
- 监控为减少时间成本而主动提前失败的退化行为；若出现，先报告终止轨迹与分项回报，再单变量调整时间/失败项，不用额外“自动救援”掩盖问题。

### 4.3 终止定义与计步

建议每回合600次决策/3000物理步、60s。Agent.MaxStep按实际Agent调用节奏核验，不直接把“600”误设为600物理步；同时用环境物理时钟执行60s上限，timeout明确作为本任务失败计分，不与训练器轨迹片段截断混淆。

掉落定义：躯干进入底层地面下方0.30m的kill区域；或已稳定登层后，无抓握地落回底层地面并持续0.30s。一级平台上合法的松手和落稳不判掉落。不可恢复断裂：从公开Grabbed/GrabRequested/NeedsRearm转换推断意外失握，2s内既未重新抓住也未稳定支撑才失败；成功恢复则继续。物体越界按环境固定边界判定；本轮箱子冻结，主要验证角色边界和计时，保留后续动态物体事件语义。默认倾倒只诊断，保持结构专项才将倾倒设为失败。

## 5. 课程与多级瓶颈

| 阶段 | 结构/特征重点 | 要学习的转换 |
| --- | --- | --- |
| C0 | 固定单箱，随后相同形态的不同尺寸/位姿 | 双手够点、撑起、越过前缘 |
| C1 | 两级台阶，宽暴露顶部、无间隙/悬挑 | 一级稳定→释放旧握点→重新武装→第二级 |
| C2 | 2–3支撑层，混合0.5/1m面、轻悬挑或小间隙 | 局部几何选择与重复转换 |
| C3 | 3–4层，组合悬挑、缺顶面竖直段、间隙与更高目标 | 长时序记忆和跨形态泛化 |

课程使用实际形状特征，不用横档间距或脚本成功格。身体参数固定；弱力量/短臂长只在锁定checkpoint后做换身体评估。对每个阶段保留低级结构回放，建议当前阶段60%、之前阶段30%、已见其他特征10%；未开放阶段不提前混入。进入新阶段后不能仅看总成功率掩盖两级转换退化。

推进条件建议：至少50万在线决策的该阶段训练量；独立验证集上结构平均成功率≥80%，95%结构聚类bootstrap下界≥70%，连续3次、间隔至少10万在线步的验证满足；旧阶段成功率下降不超过10个百分点。未达标则停留，不增大力量、不把复杂结构过滤掉。验证用固定留出集合，不参与梯度；推进后的失败分布与退化也记录。

诊断分解记录：到达第一层比例、第一层稳定后到第二层的条件成功率、两次抓握之间无支撑时长、重新武装失败、二层前掉落/超时、最高稳定层数、完成时间。阶段指标可由评估端内部几何判定，但不输入策略。三级以上不默认为物理可解，应从失败轨迹区分粗几何误判、感知遗漏和学习瓶颈；不回头用专家过滤训练分布。

本轮试跑全部从正常结构底部出生。正式训练的主要探索辅助手段改为示范状态初始化，比例和状态合同见第10节；本轮不实现。

## 6. 示范与对照

### 6.1 可以利用现有脚本，但不能直接录现有组件当作demo

现有BoxClimbSmokeController直接调用身体，且每物理步运行；拟定Agent为10Hz增量动作。必须先做专家适配：让专家产生同一个6连续+2离散动作，经相同目标积分、努力值、身体接口执行。不能专家直接施加绝对目标、再记录一个未真正执行的增量动作；动作饱和时不能仅剪裁标签而不重跑轨迹。既有脚本2.60s/约5s的成绩不自动迁移到新动作接口。

专家适配必须先在单箱/两级16场地复核，用Agent的Heuristic/同一动作通路和DemonstrationRecorder记录同步观测、实际动作、回报与终止。不能只给原控制器挂Recorder：本机包源码要求同对象存在Agent。记录固定物理频率、决策周期、接口版本、身体、结构hash、专家版本和成功/失败，不将专家阶段/tier加入策略观察。

录制后核对demo的实际条目/模拟秒与10Hz合同一致；若录制路径包含中间物理步，必须统一采样/记录通路后再使用，不能把50Hz序列当成10Hz动作训练。

建议只录简单单箱/两级训练结构，至少200条完整轨迹，分段均衡抽样第一层、释放/冷却、第二次够点和翻越，避免大量静止抓握帧淹没稀有转换。示范结构不得进入最终测试集。专家读取固定关卡路线属于特权教师信息，必须披露；学生仅有327维局部观察。示范采集失败应保留诊断，不能据此从RL训练结构中删除关卡。

### 6.2 主对照

| 组 | 在线算法 | 示范辅助 | 目的 |
| --- | --- | --- | --- |
| A：不用示范 | PPO + 相同外部奖励 | 无 | 探索/信用分配基线 |
| B：主要方法 | 同PPO | 示范中间状态初始化，不做BC | 缩短第二级转换的探索距离 |
| C：行为克隆对照 | 同PPO | 正常底部出生+初期BC，随后退出 | 区分状态初始化收益与动作模仿收益 |

A/B/C各5个配对训练种子，网络/动作/观察/身体/奖励/在线步预算相同。初步预算500万在线决策，100万步间隔保留checkpoint；是否扩到2000万由试跑预算和独立验证决定，不按测试集结果追预算。主对照使用试跑后预注册的共同课程分布日程，避免辅助组更早升级导致各组结构分布不同；按成功率自适应推进作为另一个课程实验，不与示范主效应混为一谈。

C候选行为克隆strength=0.1、steps=200000、独立demo_path；初期辅助后转纯PPO，实际衰减/停止语义在配置实现时按安装版本核验。A无示范模块，B无BC模块。报告等在线步比较，同时报告示范环境步、BC更新量、采集/训练总耗时；B/C的额外数据和计算不能隐去。B需先通过状态恢复验证，C需通过动作适配验证；分别满足后才启动。

GAIL作为后续可选附加组，不与BC同时加入首个对照：外部奖励保持，GAIL强度候选0.05–0.1，与extrinsic分别记录；use_actions=false作为起点以减少固定动作风格约束。它可能奖励“像专家”而非完成任务，尤其只见过两级会压制新的多级解法；须检查判别器过拟合、停在示范状态刷奖励、分布外动作被惩罚及回报尺度。没有验证收益前不默认启用。

主要偏差：脚本只覆盖少数固定路线、无恢复动作、依赖绝对路线、动作频率/分布与学生不同、示范高成功但窄多样性。BC可能复制错误抓放节奏，GAIL可能偏好旧高度范围。示范改善训练内成绩而损害新形状/换身体成绩也须如实报告。

## 7. 评估规范

1. **结构划分**：训练/课程验证/最终测试按实际几何与质量的规范化hash去重，不只按随机seed分割；相同箱体堆叠的平移/yaw变化仍算同一个结构。最终测试包含同分布新结构、单特征外推和组合外推。只以物理稳定性/粗几何准入，报告候选总数、拒绝率和原因，不能挑脚本会爬的结构。
2. **数据容量前置检查**：当前Easy主要是单箱三种缩放和固定两级模板，不足以声称大量独立结构。完整统计前需定义同类箱体的尺寸/布置变化与足够独立结构；不足时报告真实n，不把16个场地复制当16个结构。正式多种子对照前，每个难度必须冻结至少50个几何独立结构；当前生成器达不到则先扩展几何多样性，不能降n绕过门槛。本轮试跑豁免，不扩展生成器。
3. **训练种子**：建议5个（例如2026–2030），A/B/C配对初始化与候选采样随机流，保留逐seed结果，不只报最佳seed。
4. **多个checkpoint**：预注册100/200/300/400/500万在线步的5点曲线。模型选择仅使用验证集，锁定后一次性跑测试；同时报告各预注册checkpoint，不在测试集上挑峰值。若未到500万，报告实际完成点和原因，不补造曲线。
5. **确定性推理**：不采样连续/离散动作、不加探索噪声；使用训练同款归一化与动作后处理，首版无记忆；后续记忆对照每回合清零。ONNX推理与训练端确定性输出做一致性检查。记录Unity/推理版本、物理步长、决策周期；“确定性动作”不保证跨设备PhysX逐位一致。
6. **采样单位**：正式实验每个难度至少50个唯一结构，三个难度至少150个；另报层级/特征分层覆盖度，不把单难度50个再拆成每子层50个。数量不足就暂停正式对照，试跑不受此限制。每结构预先固定4个出生/朝向扰动条件，所有模型使用相同条件。结构得分s_i=该结构4回合成功均值；总成功率为mean(s_i)，每结构等权。
7. **置信区间**：每结构只有一次二元结果时可用Wilson 95%区间；4次重复时不能将800回合当800个独立样本，采用结构级cluster bootstrap（10000次，整组重采样）给95%区间。比较A/B/C保留同结构配对。跨训练seed额外报告均值、离散程度和各seed点；总体区间用先训练seed、再结构的分层bootstrap，不能把所有相关回合摊平。
8. **专项指标**：每层级/悬挑/间隙分层成功率、第二级条件成功率、完成时间、最大稳定高度、掉落/超时/断裂后不可恢复/越界占比；同时给全部结构无条件成功率，避免仅在“到过一级”的子集制造好成绩。
9. **换身体测试**：固定结构、checkpoint和策略，另测较弱力量及短臂长，每次只改一个因素，再测组合。默认训练身体不削弱；具体评估数值在实验前预注册。臂长改变须在身体初始化时同步真实关节限制、动作投影和观测尺度，不能只改一个public字段造成名义/物理不一致。作为泛化测试披露物理不可达结构占比，不混入默认身体成功率。

## 10. 示范状态初始化（主要方法，暂不实现）

从脚本完整攀爬轨迹采样合法中间状态，重点覆盖一级已落稳、旧握点释放/冷却、准备够第二级及第二级起撑。正式训练初期50%正常底部出生、50%示范状态出生；后者的70%取一级到二级转换附近、30%取其他攀爬阶段，按轨迹均衡，不按停留帧数过度采静止状态。每个回合标记出生来源，仅供日志，不作为观察。

状态必须包含三个刚体位姿/线角速度、手目标与努力渐变、抓握锚点/连接、抓握请求/重新武装/冷却、奖励去重和进展缓存。当前公开ResetBody只支持统一旋转、位置和清零速度，不能正确恢复一般带抓握的动态快照；未来需在身体内部增加受控快照恢复接口，控制器不得直接操作Rigidbody或Joint。本轮不新增该接口，不能用瞬移躯干伪造示范状态。

恢复后检查穿透、臂长、锚点、稳定性，复算局部观察；若需要短暂物理落定，应计入恢复协议并验证不改变关键状态。已完成的一级不得重新发奖，奖励总额和终点判定从同一完整任务视角计算。示范仅取训练结构，评估集禁止用于状态库；采集失败不导致训练结构被脚本过滤。

为避免只会从中间开始：正常出生占比始终至少50%；后半程将示范占比从50%线性降到20%，最后10%预算完全正常出生。课程推进和所有主评估只看正常底部出生结果；额外报告中间出生的条件成功率，不能合并伪装成完整任务成功率。报告最高稳定层数、第二级条件登层率与正常出生的分阶段转化差距。

A=PPO正常出生；B=PPO混合状态初始化（主方法）；C=PPO正常出生+BC（对照）。在线预算、结构分布、网络和奖励一致，出生分布差异正是B的干预；示范采集成本、额外恢复开销和BC计算分别报告。GAIL不纳入首轮。

## 11. 冻结评估集的独立判定

正式多种子对照前，Easy/Standard/Hard各≥50个稳定、粗几何通过的独立结构，固定manifest与SHA-256且与训练/课程验证无交集。独立按静态接触/支撑图、箱子尺寸/相对位姿、暴露顶面与目标位置定义；仅seed、对象ID、排列顺序、根平移/yaw、出生扰动不同不算新结构。

用根平移/yaw规范化、按几何排序、0.05m网格量化的几何hash去重，只计箱体尺寸、相对位姿与支撑关系；仅质量、材质、目标位置或出生条件变化不算几何独立。完整manifest另用SHA-256记录质量、目标等全部内容；对近重复再按相同支撑图及尺寸/位置最大差≤0.05m聚类，整个簇只能进入一个集合。镜像等价结构也归同簇。几何独立不等于统计生成完全独立，报告生成方式、簇数和形状覆盖度。不得以脚本成败挑选评估结构。

本轮10–15分钟校准只用固定两级台阶、正常底部出生，允许单一结构；不得据此宣称泛化或正式成功率结论。

## 12. 本轮实现约束

Agent仅通过公开身体命令/快照操作；SDK自动MaxStep设0，由环境的60秒或600次决策预算明确给出失败奖励，不产生隐式截断。DecisionRequester周期5且TakeActionsBetweenDecisions=false，目标增量与时间惩罚只在新动作时结算；努力值根据Grabbed每物理步选择，自由1.0/抓握0.7，仍遵守身体渐变。自有Academy时钟在身体FixedUpdate前运行，不修改fixedDeltaTime或ProjectSettings。

静态环境感知使用层8（可抓表面）和数值层9（其他环境）查询，角色保留原层0；只在新训练场景内给环境分配层，不改项目层名或碰撞矩阵。射线和净空只查询同场地，排除角色；默认身体、原关卡及脚本不变。登层统计的第一/第二级高度阈值仅用于固定两级试跑的诊断，不进入观察或奖励，奖励用局部稳定支撑的历史进展。

试跑不启用示范状态、BC或循环记忆。新run-id、正常底部出生、16个相同两级结构副本，不能把它们当独立评估结构。计划总墙钟约11分钟，前60秒预热，后600秒测端到端训练率；优化更新以CUDA同步包围计时，另外记录PyTorch分配/保留显存及整卡占用，注明口径。

本轮登层率采用固定两级的累计稳定支撑高度阈值（≥0.45m、≥0.95m），不是直接输入策略的层号，也不证明逐一踩过每个中间面。正式多级评估应另列按真实支撑面和访问顺序定义的条件转换率。

## 13. 手目标表示开关（incremental / absolute）

依据见[LAYER3_PILOT_DIAGNOSIS.md](LAYER3_PILOT_DIAGNOSIS.md)第2.5节和第5节。这是单变量对照，动作维度、观察、抓握请求、努力值、奖励、身体和PPO超参都不变。

### 13.1 选择方式

- `ClimberAgent.TargetMode`默认值为`Incremental`，因此不设置参数时与试跑完全一致，旧结果可以复现。
- 训练YAML通过`environment_parameters.target_mode`设置：0为incremental，1为absolute。Agent在每回合开始时用`Academy.Instance.EnvironmentParameters.GetWithDefault("target_mode", TargetMode)`读取（本机包`Runtime/EnvironmentParameters.cs`）。其他值直接抛异常，不做静默回退。
- 两份对照配置是`config/climb_target_incremental.yaml`和`config/climb_target_absolute.yaml`，两者唯一的差别是`target_mode`。`climb_pilot.yaml`不修改。
- 相对试跑配置，这两份配置还有以下非学习参数不同，两组相同：`max_steps`=5,000,000；`checkpoint_interval`=500,000；`keep_checkpoints`=20；`torch_settings.device`=cpu。

### 13.2 映射

每只手的连续动作a∈[−1,1]³（Agent先逐分量裁剪），在躯干坐标、肩部为原点下：

| 模式 | 每次决策更新 |
| --- | --- |
| incremental | q ← Project(q + 0.08·ClampMagnitude(a,1))，最大0.08m/决策 |
| absolute | q = Project(0.85·ClampMagnitude(a,1))，与上一次的q无关 |

- Project把半径夹到[0.15, 0.85]m（零向量映射为向上0.15m），与身体`SetHandTarget`使用同一个目标球壳。
- absolute的取值范围：单位动作球线性映射到半径0.85m的球，再把半径小于0.15m的点径向推到0.15m球面上。动作球中|a|<0.176的小球全部落在内壳上，|a|=1落在外壳上。
- 动作立方体的角（|a|>1）被ClampMagnitude压到外壳。因此均匀随机动作约有1−π/6≈48%的时间位于外壳上。absolute下的“贴边比例”表示策略选择伸直手臂，含义与incremental下的“积分漂移贴边”不同，两组报告时不能直接按同一含义比较。
- 回合开始时，在第一个动作到来之前，q仍取ResetBody后手相对肩部的实际位置，两种模式相同。观察中的“当前命令目标”字段始终是q，维度和缩放（÷0.9）不变。

### 13.3 与身体目标限速的配合

身体每个物理步执行`targets ← MoveTowards(targets, requested, 1.5m/s·0.02s)`，即每步最多0.03m，每次决策（5个物理步）最多0.15m，然后用这个滤波后的目标做PD控制。

- absolute命令可以在两次决策之间跳变，最大为外壳直径1.7m。身体会把这次跳变摊开到最多约1.7/0.15≈12次决策（1.13秒）内完成，所以不会出现瞬时的大PD误差或力突变。PD的力预算（自由手40N，抓握手315N）也不变。
- MoveTowards沿直线移动，跨越肩部附近时滤波目标可能暂时进入半径小于0.15m的区域，这与incremental下的抓握重置行为相同，PD仍有限幅。
- incremental的0.08m/决策小于身体的0.15m/决策，所以滤波目标几乎总能跟上q。absolute下，较大的跳变会使滤波目标落后q最多约1秒。这是该表示的固有代价，不额外加平滑。
- 抓握瞬间，身体把requested和targets重置为当前手的位置。Agent在下一个物理步重新提交q，两种模式都从这个位置以1.5m/s移向q。

### 13.4 最小有效动作（经验规则）

- **自由手**：重力9.81N，弹簧900N/m，稳态下垂约1.1cm，力预算40N约为重力的4.1倍。absolute下动作变化Δa使目标移动0.85·Δa；Δa=0.05对应4.25cm，大于下垂量。PlayMode测试`SmallAbsoluteActionMovesFreeHandAgainstGravity`验证：Δa_y=0.05使自由手稳态升高3–6cm。
- **抓握手撑起**：要单手把整个身体（117.72N）向上推，PD误差需要≥117.72/900≈0.13m，目标需位于手下方约0.13m处，对应Δa≈0.15；力预算315N足够。incremental下q每次决策最多移动0.08m，从外壳上的位置（试跑策略抓握时96.8%在外壳上）移到握点下方，需要多次连续同向的决策；具体次数取决于抓握时q的方向，而这个方向没有逐向量记录。

### 13.5 本轮实现边界

只实现开关和测试。不改观察、奖励、努力值和身体。对照实验的协议与结果见`LAYER3_TARGET_REPRESENTATION.md`。

**验证**：

## 14. 躯干高度新高奖励（单变量消融，默认关闭）

背景：§4.2规定首版不加高度shaping，若稀疏学习失败，另做单变量消融。示范状态初始化之后，S1b→一级、S3→二级仍学不会（[LAYER3_DEMO_INIT.md](LAYER3_DEMO_INIT.md)），因此在`climb_demo_init.yaml`的基础上只加这一项。结果见[LAYER3_HEIGHT_SHAPING.md](LAYER3_HEIGHT_SHAPING.md)。

### 14.1 公式

设y_t为第t个物理步的躯干高度（场地局部坐标），y*为本回合的最高值，R为本回合已发放的高度奖励：

- 初始化：y*_0 = 回合开始后的躯干高度。地面出生时取ResetBody之后的值；快照出生时取RestoreState恢复后的值。快照中记录的历史最高值`maximumHeight`只作为指标，不用于计算这项奖励。
- 每个物理步（`BeforePhysics`，与进展判定在同一处）：
  - 若y_t > y*：r_t = min(k·(y_t − y*), C − R)，然后y* ← y_t，R ← R + r_t；
  - 否则r_t = 0。
- 参数：`height_reward_scale`=k（每米），`height_reward_cap`=C。
  - 代码默认k=0、C=0，即关闭，此时不调用AddReward，也不输出`Climb/RewardHeight`。
  - 本轮配置`config/climb_height_shaping.yaml`：k=0.2/m，C=0.2。
  - Agent强制C < 0.3（现有进展奖励的总上限），否则在回合开始时抛异常。
- 量级（【推断】，按出生躯干0.4m、两级台阶顶面0.5/1.0m估算）：
  - 站上一级时躯干约0.9–0.95m，地面→一级约+0.1；
  - 二级约1.45m，一级→二级再约+0.1，达到上限。
  - 与每级的+0.1进展奖励同量级，远小于终点+1。

### 14.2 为什么来回晃动刷不了分

- 整个回合的高度奖励总和可以逐项相消，结果是Σr_t = min(k·(y*_T − y*_0), C)。它只取决于本回合达到过的最高点，与路径无关。
- 回落后再升回原高度，在超过y*之前r=0。原地上下晃动、反复抓放、跌落重爬都不会再拿到奖励。
- 每个回合最多拿到C=0.2，与持续时间和动作次数无关。
- 快照出生时y*_0取恢复后的高度，所以快照本身的高度不发放。快照的进展账本沿用§8，已付过的支撑不重复支付。
- 已知的剩余风险（【推断】，训练时监控）：
  - **瞬时峰值**：躯干被甩高后掉落，也会按峰值付一次。不能重复，总额也受C限制。但"甩高后坠落"比"停住超时"少付时间成本（≤0.12）。监控`Climb/End/Fall`，并与示范初始化对照比较。
  - **非势函数**：y*依赖历史，这项奖励不是基于势函数的shaping，不保证最优策略不变。因为C + 0.3 < 1，成功仍然严格优于任何不成功的回合。
  - **零动作也能拿到**：【数据】零动作策略（hold）从S1b出发平均能拿到约0.073（32回合，最大0.118，均未到一级），因为抓住后手臂弹簧会把躯干往上拉。地面出生的hold为0，说明落定不产生奖励。从S2出发平均约0.001（最大0.008）。这部分是起点状态自带的，与S2的进展奖励类似，评估时用hold基线对照。

### 14.3 验证

- PlayMode 64/64。新增4项：
  - `HeightShapingIsOffByDefault`；
  - `HeightShapingPaysOnlyNewEpisodeHighsUpToCap`：5次往返只付一次，总额到0.2截止；
  - `HeightShapingStartsFromRestoredSnapshotHeight`；
  - `HeightShapingCapMustStayBelowProgressCap`。
- 关闭时可复现：用新构建、`target_mode=0`重跑试跑checkpoint 50回合，与`docs/data/climb-grip-diagnostics/checkpoint`逐回合比较：50/50回合、64/64运行时行一致。

### 17.1 示范起点在新结构上如何处理

现状：状态库`results/climb-snapshots-v2/library.jsonl`只来自训练两级台阶；S1a/S1b/S2/S3这些阶段标签也是按两级台阶的事件定义的。

| 方案 | 做法 | 优点 | 问题 |
|---|---|---|---|
| A. 只在有状态库的结构上使用 | 抽到训练两级台阶时，沿用50%示范出生；其他结构只用地面出生 | 不新增录制；不引入"按脚本能否完成"划分出生方式的偏差；改动最少 | 整体示范出生比例下降：两级台阶占25%时，从50%降到约12.5% |
| B. 用脚本控制器在它能完成的新结构上补录 | 用`BoxStackScriptController`在训练池结构上录轨迹；能完成的结构有示范出生，其余只有地面出生 | 示范覆盖更多结构 | 需要把录制器和阶段定义推广到任意层数；示范起点只出现在"脚本可解"的结构上，等于按脚本成败给结构分了两类出生方式，与"脚本结果不用于筛选"的精神相冲突；同时改变了出生分布和结构分布两个变量 |

**选择：方案A。**
1. **单变量**：这次实验要回答的是"在结构分布上训练能否学会新结构"。方案B同时引入新的状态库和新的阶段定义，失败时无法归因。
2. **证据**：修复后，两个5M策略在训练两级台阶上从地面起点的成功率已达99.5%/100%。【推断】在新结构上，从地面学习的路径（高度奖励 + 进展奖励）已被证明可行；示范的主要作用是早期引导，两级台阶上保留示范出生就能维持这一点。
3. **避免偏差**：方案B会让"脚本可解"的结构获得额外的训练起点。审计（§16）显示脚本可解与否和"0.5m矮层 + 偏移"等特征相关，这会把训练分布往脚本擅长的结构倾斜。
- 若C1的成功率停滞（例如4M步后，验证集上低于C0晋级门槛的一半），再把方案B作为下一个单变量实验。
